# VIVIAI 内部运营平台：产品需求与总体设计

日期：2026-09-09。版本：v0.1 评审稿。用户已确认“内部团队使用”；实施分期、权限规则和界面方向为本稿建议，等待评审，不代表获准实施。

本轮仅交付设计，没有开发后台页面、管理 API、数据库迁移，没有启用真实模型、收款、退款或部署。已有创作前端仍为 Mock。本文是总体蓝图及一期需求基线，不把全部子系统塞进一个实施计划；各增量在设计确认后独立拆解、实现和验收。

## 1. 产品定位与成功标准

运营平台服务于内部负责人、客服、财务、模型运营、内容运营和系统管理员。单一运营主体，不做代理商后台、租户开通、分销结算或用户团队空间。

第一性原则：每次图片生产同时产生用户体验、积分变化、供应商成本和数据访问风险。平台必须让团队知道“发生了什么、依据是什么、谁能处理、处理后如何验证”，而不只是展示数据库表格。

核心目标：

1. 客服通过用户、订单或任务标识完成问题定位，无需进入数据库。
2. 每次扣退积分、补偿、现金退款、费用调整均有独立业务凭证与幂等保障。
3. 型号、分辨率、比例、实际像素和采购/售卖价格可追溯，不能静默降级。
4. 未知上游执行与未知费用有待办和责任人，不自动当失败重发、不记成零费用。
5. 高风险操作经过复核；隐私访问和配置变更有审计。

一期验收目标：上述五项在离线端到端测试中成立；真实商户/模型开通是另一个验收门槛。响应时间和经营数值是验收目标或真实计算结果，不用演示数据充当线上事实。

## 2. 现状、可复用能力与差距

依据现有代码而非长期路线图判断“已实现”：

| 领域 | 当前实际能力 | 运营平台需要新增 |
| --- | --- | --- |
| 账号 | 普通用户、邮箱验证、会话、登录限流 | 独立管理员身份、MFA、角色权限、用户限制策略 |
| 积分 | CreditLot / Reservation / Allocation / Event，冻结、消费和释放 | 管理读模型、补偿申请与审批、退款权益预留、审计 |
| 支付 | 微信/支付宝创建、查询、验签、幂等积分履约；默认未开通 | 管理订单列表、售后单、原路退款协议与恢复、支付账单导入 |
| 生成 | Job → Item → Attempt，恢复、私有结果、用量记录 | 管理查询、异常工单、受控处置、证据与权限 |
| 模型 | 五款官方型号适配器、能力白名单、价格/执行快照 | 配置草稿、审批发布、历史版本保留、运行时生效确认 |
| 配置 | 官方模型 JSON 与支付商品文件在启动时加载 | 持久化控制配置、原子版本指针、版本解析和停用门禁 |
| 成本 | 用量与冻结价格计算、未知成本预留、账号预算/配额 | 账单核对、追加费用修订、未分配账单、经营报表 |
| 内容/工具/工作流 | 主要是前端演示及设计 | 对应业务后端和管理模块，不能仅用后台 CRUD 声称打通 |

CreditLot.revenueMinor 当前记录订单实收总额，不是扣除退款、手续费后的净收入。ProviderUsageRecord.actualCostMicros 是现有运行时费用计算结果，不自动代表已经核对供应商发票或账单。

## 3. 方案选择与系统边界

推荐：独立运营前端 `viviai-admin`，现有 NestJS 中增加管理模块，复用业务应用服务和 PostgreSQL；后台独立域名/同源代理入口，管理会话与普通用户会话隔离。

| 备选 | 优点 | 代价与结论 |
| --- | --- | --- |
| 独立前端＋现有模块化后端 | 权限界面分离，复用账务和任务规则 | 需管理身份、查询与命令接口；推荐 |
| 用户端增加管理员菜单 | 起步快 | 容易混合 Mock、用户缓存和高权限入口；不选 |
| 全新后端和独立业务库 | 发布隔离强 | 重复账务规则、数据同步和一致性成本过高；当前不选 |

逻辑边界：管理员浏览器 → Admin API → 权限/审批/审计 → 既有或新增业务应用服务 → 事务及 Outbox → Worker/支付/模型适配器。报表使用查询层或可重建聚合，不通过报表反写账务。

不拆微服务、不复制用户/钱包/订单事实库、不把完整 Prisma 模型直接暴露给前端。不提供任意 SQL、脚本执行、任意供应商 URL 或任意 JSON 参数透传。新增模型协议仍属于代码审查事项，不能由运营配置字段绕过。

## 5. 角色与权限矩阵

角色是权限模板，可以一人兼任多个角色，但同一人不能审批自己发起的高风险操作。无需为了六种角色配六名员工；资金/发布流程至少要有两名不同的实名管理员。

| 能力 | 负责人 | 客服 | 财务 | 模型运营 | 内容运营 | 系统管理员 |
| --- | --- | --- | --- | --- | --- | --- |
| 经营概览 | 全局 | 服务指标 | 财务指标 | 模型指标 | 内容指标 | 系统指标 |
| 用户/订单/积分查询 | 可 | 脱敏可 | 财务必要字段 | 不可 | 不可 | 默认不可 |
| 私有提示词/图片 | 不随角色自动授予，均需独立权限、业务单和访问理由 | 同左 | 同左 | 同左 | 同左 | 同左 |
| 发起补偿/退款 | 可 | 可 | 可 | 不可 | 不可 | 不可 |
| 复核补偿/退款 | 可 | 不可 | 可 | 不可 | 不可 | 不可 |
| 采购/销售价格草稿 | 可 | 不可 | 可 | 可 | 不可 | 不可 |
| 价格/商品发布复核 | 可 | 不可 | 可 | 不可 | 不可 | 不可 |
| 渠道参数草稿 | 可 | 不可 | 不可 | 可 | 不可 | 不可 |
| 凭据写入/轮换 | 需单独安全权限与复核 | 不可 | 不可 | 默认不可 | 不可 | 可申请，不可读取明文 |
| 紧急暂停新调用 | 可 | 不可 | 不可 | 可 | 不可 | 可 |
| 账单导入/匹配/调整 | 查询/复核 | 不可 | 可发起，不可自批 | 可查相关脱敏费用 | 不可 | 不可 |
| 内容发布 | 复核 | 不可 | 不可 | 不可 | 草稿/提交 | 不可 |
| 管理员与权限 | 复核 | 不可 | 不可 | 不可 | 不可 | 申请/配置，不可自增权 |

权限同时检查功能、数据范围、字段和动作；菜单隐藏不替代服务端检查。审批时与执行时都重新验证角色、申请人身份和对象版本。角色撤销立即失效，不能等待旧 Cookie 到期。

首版所有手工赠分、现金退款、费用修订、价格发布、提高预算/并发、权限提升、密钥轮换均双人复核，不设置自动免审金额。紧急暂停可以先执行后通知与审计，恢复/扩大能力仍须复核。仅一名管理员时保留查询和暂停能力，不提供“超级管理员自批”后门。

### 管理员身份基线

- 无公开注册；一次性邀请绑定指定邮箱，24 小时过期。首次负责人通过受控离线引导建立，不预置固定密码。
- 独立 AdminAccount / AdminSession；MFA 首版采用 TOTP 与一次性恢复码。邀请接受后必须完成 MFA 才获得业务会话。
- HttpOnly、Secure、Host-only Cookie；管理端变更请求校验 Origin/CSRF。管理与用户会话不能互用。
- 会话默认空闲 30 分钟、绝对 8 小时过期；高风险申请和审批要求 5 分钟内重新完成 MFA。
- 恢复码仅创建时展示，服务端存散列；TOTP 秘密加密保存。重置 MFA 撤销旧会话并通知本人，不能只凭客服判断。

A 使用预定义只读角色和受控离线引导邀请，建立两名不同的初始管理员；这是部署引导程序，不是公开管理 API，也不自动执行资金操作。A 的角色页面只读，在线邀请/权限变更及其双人审批从 B 开放，避免依赖尚未实现的审批引擎。初始配置、紧急撤销账号均留痕；后续不得用引导程序绕过在线权限审批。

## 6. 信息架构与通用交互

建议导航：

```text
工作台
  运营概览 / 我的待办
用户服务
  用户 / 生成任务 / 服务工单 / 积分与补偿
交易财务
  支付订单 / 退款单 / 账单对账 / 经营分析
模型经营
  产品模型 / 供应商账号与渠道 / 商品与定价 / 发布记录
内容运营（二期）
  公告 / 灵感与授权示例 / 分类标签 / 活动
系统管理
  管理员与角色 / 审批中心 / 审计日志 / 告警与运行状态
```

列表默认 30 条、最大 100 条，使用稳定游标；时间筛选存 UTC、默认按 Asia/Shanghai 展示，明确时区。查询条件可分享为 URL，不能包含密钥、原始提示词或图片内容。全局搜索首版仅支持精确用户 ID/邮箱、订单号、Job/Item ID，不做对用户私有提示词的全库搜索。

状态必须区分：加载、真实空数据、未接入、无权限、服务错误、数据过期、操作处理中/结果未知。金额和大整数在 DTO 中使用十进制字符串；明确 CNY 分、USD 微元与积分单位。

动作由后端返回 allowedActions 和不可用原因，执行时仍重新校验。不乐观显示退款/补偿/发布成功；变更中只显示“处理中”，根据持久化动作记录查询最终结果。

A 阶段不开发控制台导出；C 阶段财务导出作为有权限的异步任务，默认只含脱敏必要字段、最长 31 天、最多 10 万行，超限要求缩小范围。下载链接单用户、短时有效并记录访问；CSV 文本列防公式注入。

## 7. 页面需求

### 7.1 运营概览与我的待办

| 区域 | 内容 | 下钻/动作 |
| --- | --- | --- |
| 环境与数据状态 | 测试/生产、模拟/真实过滤、统计时区、数据截至时间 | 查看数据口径与刷新 |
| 现金概览 | 支付确认实收、已确认现金退款、支付手续费数据覆盖 | 订单/退款/支付账单 |
| 生产状态 | 创建任务、成功交付张数、终态交付率、排队和交付耗时 | 带筛选的任务列表 |
| 成本与预算 | 用量计价、账单核对金额、未知笔数、预算已占/已耗 | 费用与账号预算 |
| 待办 | 付款履约异常、超时/未知、落盘失败、审批和对账差异 | 工单详情与负责人 |

首页只展示当前角色可以查看的指标。未收集的活跃用户、留存、下载转化不能从订单量推测；二期增加事件采集后才展示。

待办按业务对象/异常类型去重，包含严重度、首次发现、最近发现、持续时间、负责人、下一步和关联证据。A 只读；B 开放领取与工单关联，领取用版本锁避免双人重复领单；通知送达失败不代表工单丢失。

### 7.2 用户列表与详情

列表：用户 ID、脱敏邮箱、用户名、注册时间、账户限制状态、可用/冻结积分、已确认支付累计、未完结工单数。筛选：精确用户、注册区间、有无支付、限制状态、异常状态。

详情页签：概况、积分批次/流水、订单、生成任务、工单、运营记录。批次展示来源、issued/available/held/consumed/expired/revoked、有效期及关联订单；不得用一条汇总余额掩盖批次归属。

允许：发起补偿、建立工单、申请或执行权限内的账户限制。禁止：读取密码/会话令牌、模拟用户登录、直接编辑余额、删除支付/流水历史。

账户限制按目的区分“停止新支付”“停止新生成”“暂停新登录”；不自动删除资产、不撤销历史订单、不阻断验签回调和在途结算。恢复要说明原因并复核。限制检查需要新增用户状态与各受理入口门禁，不是只改列表标签。

### 7.3 积分与补偿

补偿申请字段：用户、关联工单/任务、原因分类、说明、正整数积分、有效期、预算归属。首版不提供手工负向调整；资金退款的权益回收走独立流程。

批准后在钱包事务中创建新的赠送批次和不可重复的 CreditEvent，sourceId 绑定补偿单 ID，收入为零。不得改原付费批次收入，不把原积分释放再记录成一次赠分。

同一事故已发生的自动释放、历史补偿在申请前展示，审批人明确确认是否仍需补偿。首版补偿预算与账本同在 PostgreSQL，预算扣减与赠分在同一事务提交，超预算则拒绝；不引入跨系统补偿预算。

### 7.4 支付订单与售后

列表：订单号、用户、商品快照、支付渠道、金额/币种、支付状态、权益履约状态、创建/支付/履约时间。支付状态与积分是否到账分开展示，未知不能归类为“未支付”。

详情：商品版本、商户身份脱敏快照、上游交易标识、已验签事件摘要、同步记录、积分批次、退款与工单。用户点击“已支付”不是资金证据。

“同步支付状态”按原订单号查询；供应商明确成功后复用原有幂等履约入口。管理 API 不能接受管理员传入 paid=true、金额或伪造通知来补单。网络异常保留原单查询，不创建第二笔收款。

当前商品是固定有效期积分包，没有自动续费和按月发放权益。后台商品字段只允许名称、版本、人民币整数分、积分、有效天数、展示状态；不能售卖未实现的并发权益或订阅能力。

### 7.5 现金退款（C 增量）

首版仅支持：已确认付款且已履约、该订单关联积分批次完整存在、无消费/冻结/过期/撤销的整单原路退款。检查式：available=issued 且 held=consumed=expired=revoked=0。申请不支持自定义收款人或换渠道退款。

已消费、部分退款、积分已过期、复杂赠品联动和外部人工退款进入例外工单，记录证据并另行设计，不用按钮假装已支持。对外退款政策需由业务确认，本节只定义首版系统执行边界。

退款流程：

1. 申请人选择订单，系统算出可退金额和权益影响；双人复核。
2. 执行时锁钱包、复查订单/批次/退款版本及累计已退金额，预留全部可用权益到独立 CreditRefundHold，禁止同时消费；持久化唯一商户退款号及退款操作后提交事务。
3. 事务外使用原商户、原订单和固定退款号调用官方退款接口；当前 create/query/notify 支付适配器需新增退款协议，不能复用支付成功回调冒充退款成功。
4. 已验签通知或可信查询确认成功后，把预留权益转 revoked、追加积分事件与资金退款事实；失败确认后归还，原有效期已过则转 expired。
5. 发送后超时进入 outcome_unknown，保留权益预留并查询同一退款号。重复点击/回调/调度不能创建新退款号或重复退钱。

仅外部退钱成功、内部结算失败时，状态为“退款已确认，权益结算待恢复”，按原凭证重放本地结算，不再次请求退款。退款号未发送前的异常可以恢复本地流程；已发送后的未知不能人为改失败释放权益。

### 7.6 生成任务与复刻详情

列表：Job ID、用户、create/remix、精确型号、分辨率、比例、实际宽高、张数、各 Item 终态计数、冻结/已扣/已释放积分、创建时间、排队/交付耗时、异常标记。费用对有权限者展示。

详情三层：Job 的用户请求和价格快照；每张 Item 的交付与钱包；每次 Attempt 的协议/账号版本、上游 ID、受理状态、终止状态、计费状态、用量与存储证据。聚合成功不能隐藏失败或迟到尝试成本。

复刻必须分别显示“用户上传参考图”和“可选主体图”的角色元数据。提示词与图像默认遮蔽；经授权可短时查看。无真实视觉分析服务时不生成虚构拆解报告，不承诺固定相似度百分比。

| 当前事实 | 后台可用动作 | 禁止动作 |
| --- | --- | --- |
| 已落盘、尚可交付、结算未完成 | 调度同一个 Item 的本地恢复，重验状态/fence | 再调用一次模型 |
| 已过交付截止但原流程未收尾 | 触发原恢复服务按状态机处理 | 直接把 status 改成功或重复释放积分 |
| 上游执行未知 | 建工单、关联供应商证据、等待核对 | 当作未执行自动重发 |
| 用户已退款后迟到出图 | 查看脱敏事件/费用证据，必要时独立售后补偿 | 复活原任务、重新扣用户积分 |
| 明确失败且用户希望重做 | 处理补偿；引导用户发起新报价/新任务 | 后台冒充用户提交收费任务 |

原任务是否可取消由既有协议与状态决定；本地中断不是供应商已停止的证据。后台不添加全局“强制成功/强制失败”接口。

### 7.7 产品模型、规格与价格

产品模型列表：产品名、精确官方 ID、文生图/参考图能力、参考图数限制、开放规格数、状态、价格版本、可用渠道、最近校验时间。

规格页采用分辨率行 × 比例列，单元格展示官方核验宽高、开放状态、限制说明和单位积分。一个共用能力白名单服务供后台、用户目录、报价、Worker 验证使用。

规则：

- 只允许从已核验能力中选择子集；未核验的 Lite 非方图及 Flash 0.5K 21:9 不允许运营强行开启。
- 不同模型同一“2K 16:9”可以有不同像素，不能在后台按比例公式统一重算。
- OpenAI 档位标注“产品预设”；实验性组合有明确提示，不冒称官方固定分辨率表。
- 当前同一型号同一分辨率各比例同售价；首版沿用该粒度。成本预览覆盖该档允许的全部比例，不能只用方图最低成本做发布判断。
- 用于真实收费的上架必须具有目标账号授权、规格验收、版本化采购价与售卖积分、预算和回滚记录；没有 Key 可以保存草稿但不能声称验证通过。

价格编辑分开采购费率与用户积分；费用维度沿用已支持的 input_text/image、output_text/image 和 Google thought token。未知维度、币种不匹配、费率缺失直接阻止发布。估价采用明确场景和输入规模假设，不承诺固定单张实际成本或保证毛利。

### 7.8 供应商账号、渠道与紧急暂停

账号维度展示：供应商、账号/项目标识、环境、凭据版本状态、配额/预算 scope、并发上限、unknown 上限、当日预留/已计费用、凭据异常。没有官方余额接口时显示“余额未接入”，不能用预算余额代替供应商账户余额。

渠道维度展示：精确模型、协议版本、固定端点类别、能力版本、启停、延迟、错误和最近上游事件。首版只管理已实现官方适配器，沿用每家官方供应商一个已配置采购账号；“账号列表”不是已实现账号池。将来同供应商多账号另行扩展，不能通过增加记录虚增同一真实账户预算。

编辑值必须受当前后端配置 Schema 与目标账号验收上限共同约束，不能只改后台表单就提高并发或放宽协议限制。

紧急暂停需要新增数据库受理门禁：在创建新的 ProviderAttempt 的受理事务中检查暂停状态。暂停生效后不再受理新尝试；此前已持久化受理的调用属于在途，可能仍发送或完成，界面明确说明。暂停不撤销旧凭据，不停止查询、结果落盘、成本核对和已验签支付履约。

待派发 Item 可等待原截止时间或按已有取消流程处理；不悄悄换型号/尺寸。预算降低到当前占用以下只阻止新受理，不把已占用金额抹掉。恢复、提高预算/并发需双人复核。

## 8. 配置版本发布与兼容迁移（C 增量）

现有运行时启动加载静态配置；控制台动态发布不能直接改环境文件并宣布即时生效。设计新增：

1. ConfigDraft / ConfigVersion 保存严格校验的非秘密配置及摘要，引用能力版本与 secretRef/credentialVersion。
2. 流程为 draft → validated → pending_approval → approved → preparing → active；失败进入 rejected/activation_failed，旧 active 不变。首版人工即时发布，不做定时发布。
3. API 与在线 Worker 预加载新配置并上报可解析的版本；只有就绪后才在数据库事务中切换 activeVersion。新进程启动必须加载活动及仍被任务引用的历史版本后才能受理工作。
4. 新报价使用活动版本；已生成且未过期的报价、已创建任务继续解析各自冻结的版本。新增历史执行配置解析器，不能沿用当前“只在最新 registry 查找旧 channelId”的方式宣称兼容。
5. 紧急暂停优先于历史报价；不能因为报价旧就绕开停用。报价是否还能受理在提交时再次检查，拒绝时要求重新报价，不能替换价格。
6. 回滚创建新发布记录并切换指针，不重写旧版本。旧账号凭据/商户验签材料在所有关联在途、未知及回调窗口完成前不能删除；具体回收须检查实际引用及提供方保留窗口。

Key 只由获准的安全操作写入服务端秘密存储；数据库和浏览器读接口只见引用、版本与配置状态。日志、审批差异、导出均不含密钥明文。首版无“测试所有模型”自动付费按钮；后续验收调用需单列测试预算、素材和人工确认。

## 9. 对账与费用处置

### 9.1 三类事实独立

| 事实 | 来源 | 不可替代 |
| --- | --- | --- |
| 用户现金 | 已核验支付/退款与支付账单 | 积分消费不是新的现金收款 |
| 用户积分 | 批次、分配、冻结与流水 | 退款/补偿不能直接覆盖余额 |
| 供应商支出 | Attempt、用量计价、账单及追加修订 | 预算预留不是实际费用 |

对账处理单同时展示执行是否终止、费用是否确定、金额是否完整、是否账单核对四个维度；不能用一个“已处理”状态全部覆盖。

### 9.2 账单导入与匹配

首版支持人工上传符合本平台明确 Schema 的标准 CSV，不承诺识别所有供应商原始格式。页面提供模板和逐列校验；不下载管理员填写的任意远程 URL。

导入字段：供应商/商户 scope、账期与时区、币种、稳定账单行 ID、上游请求/交易/退款号（若有）、金额、发生时间、账单类型、源文件摘要。缺少请求级标识的账单保留账号/账期汇总，不凭金额相近自动配到某个任务。

默认单文件 ≤10 MiB、≤5 万行；导入先预览错误与重复，确认后入库。以 scope＋账单类型＋账单行 ID 去重，并以文件摘要防止同一文件重复导入。没有稳定行 ID 时仅做去重的汇总凭证，不自动明细入账。

自动匹配需身份、币种、原始标识一致；一对多、多对一、金额差异进入人工复核。人工匹配与金额调整单独审批，绑定证据摘要及原版本，修改后原审批失效。

费用修订采用追加 CostRevision，不覆盖上游用量、最初计价和既有凭证。每次 Attempt 只采用一个当前有效费用版本，不能把 API 计价和账单金额相加。无法分配的汇总差异在账号报表单列，不能伪造逐张成本。

### 9.3 未知执行与预算解锁

- 确认供应商已终止执行，才允许通过幂等命令释放该 Attempt 的执行名额；费用未知时保留预算预留。
- 确认金额或明确不计费后，按当前费用版本结算/释放对应预算，不能靠修改配额总数修复。
- 只有总账金额匹配、没有终止证据，不能断言某个请求不再执行。无证据时保留异常工单和占用，必要时暂停新受理。
- 首版不提供“忽略风险强制清零配额/费用”的按钮。这个限制在页面明确展示，不能用管理员权限绕过。
- 人工调整需锁钱包与相关 provider scopes，并校验 Attempt 当前版本；与晚到 Worker 更新竞争时不得重复释放或让旧观察覆盖人工修订。

现有 recordCost 对已知费用采用不再覆盖策略；C 增量必须新增费用修订/预算差额协调服务，并让报表和运行时明确选择有效版本，不能直接利用现有函数偷偷改账。

## 10. 指标口径

| 指标 | 定义/边界 |
| --- | --- |
| 实收金额 | 所选时间内 paidAt 对应已确认支付金额；现金退款另列，不混支付尝试 |
| 成功交付图数 | 所选交付时间内成功 Item 数；不把 provider 成功但未交付算入 |
| 终态交付率 | 同一创建批次成功 Item / 已终态 Item；明确终态包含失败与取消，未终态另列 |
| 排队/交付耗时 | 排队从创建到首次受理，交付从创建到用户结果提交；新增时间事件支撑，不能用可变 updatedAt 猜测；历史缺事件显示无数据，不伪造回填 |
| 供应商成本完整率 | 确认不计费或存在可用金额的 Attempt / 该批次全部 Attempt；账单核对覆盖率单列 |
| 每张交付采购成本 | 同一任务批次全部关联 Attempt 的当前有效费用合计 / 成功 Item 数；零交付时为“不适用”，未知费用则标记不完整 |
| 预算使用 | ProviderBudget 的 reserved 与 consumed 分开；多 scope 不能相加当采购成本；当前账号日预算按 UTC 日期，页面注明 |
| 管理口径积分收入归因 | 按实际消费 Allocation 对应付费批次的可分配净收入分摊；赠送为零，不使用当前套餐单价乘积分 |
| 贡献毛利 | 上述收入归因－全部相关模型支出－已取得的增量费用；不是净利润，不代替企业会计核算 |

净收入分摊需要新增支付费、退款及收入分配版本。C 前不展示“已确认毛利”；C 后仍有未核对、未分配或缺失费用时，只显示带来源和覆盖率的暂估分析，不能将缺失项填 0。

美元原币与人民币原币分别保留；换算使用带日期、来源与版本的运营汇率记录，不使用浏览器实时汇率覆盖历史。比例、除法使用整数最小单位/十进制定点计算，最后展示时舍入。

按模型/规格、create/remix、付费/赠送积分、账号和任务批次筛选。现金时间报表与任务批次报表不混成一张无说明的利润图；迟到费用和后续修订以报表 asOf 时间反映，保留历史版本重现能力。

## 11. 操作、审批与工单契约

首版业务工单类型：付款履约、积分争议、生成失败、上游未知、输出质量、内容投诉、费用差异。主流程 open → assigned → in_progress → resolved → closed；需要外部信息时 in_progress ↔ waiting_external，resolved/closed 可因新证据重新打开。工单关闭只关闭跟进记录，不改变底层任务/资金事实。

高风险操作申请保存：type、targetType/targetId、targetVersion、申请参数摘要、原因、证据引用、requester、createdAt、expiresAt。审批默认 24 小时内有效；执行前对象已变化、审批过期或人员权限撤销则转 stale/expired，要求重新申请。

操作流程：pending_approval → approved → executing → succeeded / failed_confirmed / outcome_unknown；拒绝为 rejected。涉及外部副作用的 outcome_unknown 必须使用原业务标识恢复，不能重建申请绕过。

所有本地资金与发布命令要求 Idempotency-Key，唯一范围为管理员＋动作类型＋key；同 key 不同请求返回冲突。同一目标的重复不同申请仍受业务唯一性/累计限额校验。审批及执行记录包含实际操作者和权限版本。

业务结果与成功审计记录同事务提交。外部操作先持久化执行意图与 Outbox，再发送网络请求，再记录观察和本地结算；审计失败不得显示操作成功。拒绝和敏感读取也记录审计，但禁止记录原始 Key、密码、完整提示词或图像字节。

## 12. 管理 API 草案（均为拟新增）

管理基础前缀 `/api/admin`，与现有用户 SessionGuard 隔离。以下是资源/动作契约方向，不表示接口已存在；详细 DTO 在对应增量实施设计中锁定。

| 增量 | 路径/方法 | 行为 |
| --- | --- | --- |
| A | POST `/auth/login`、`/auth/mfa/verify`、`/auth/logout`；GET `/me` | 独立身份，未完成 MFA 不返回业务权限 |
| A | GET `/dashboard`、`/users`、`/users/:id`、`/users/:id/credit-lots`、`/users/:id/credit-events` | 脱敏查询、统计覆盖说明 |
| A | GET `/orders`、`/orders/:id`、`/jobs`、`/jobs/:id`、`/attempts/:id` | 订单、任务和上游分层详情 |
| A | GET `/models`、`/provider-accounts`、`/alerts`、`/audit-events` | 当前已加载配置只读；缺数据明确标记 |
| A | POST `/sensitive-access-grants`；GET `/assets/:id/preview` | 独立权限、关联用户的订单/任务与业务理由、5 分钟短时访问授权；服务端流式返回并审计，不跨用户公开；B 后关联正式工单 |
| B | POST `/cases`、`/cases/:id/assign`、`/cases/:id/transition` | 工单与版本竞争控制 |
| B | POST `/operations`、`/operations/:id/approve`、`/operations/:id/reject`；GET `/operations/:id` | 白名单动作申请与复核，不能通过任意 type 调用内部方法 |
| B | POST `/orders/:id/sync`、`/jobs/:id/recover`、`/provider-accounts/:id/pause` | 独立授权/审计；限频，复用原恢复规则 |
| C | POST `/config-drafts`、`/config-drafts/:id/validate`、`/config-versions/:id/publish` | 发布须绑定已批准操作与未变更版本；异步返回操作状态 |
| C | POST `/reconciliation-imports`、`/reconciliation-imports/:id/confirm`；GET `/reconciliation-items` | 文件校验、预览、幂等入库、差异列表 |
| C | POST `/refund-orders`；GET `/refund-orders/:id` | 创建退款申请；通过操作审批后按固定退款号执行与恢复 |
| C | GET `/reports/*`；POST `/exports`；GET `/exports/:id` | 带口径/asOf/覆盖率查询及受控导出 |

动作接收 `{reason, evidenceIds, expectedVersion, payload}` 等严格字段；payload 按动作独立 Schema 白名单验证。HTTP 202 表示已持久化受理，不表示钱已退或配置已生效。

常见错误：401 管理会话失效；403 无动作权限；404 对资源无可见权限或不存在；409 版本过期/幂等冲突/审批失效；422 业务不满足；429 限流；503 依赖或能力未启用。错误只返回安全说明、可追踪 requestId 和可用的重试方式。

## 13. 数据模型增量与业务一致性

复用 User、PaymentOrder/Event、GenerationQuote/Job/Item、ProviderAttempt/UsageRecord、CreditLot/Reservation/Allocation/Event、ProviderQuota/Budget 和 Asset，禁止复制第二套“运营余额”。

| 增量 | 新实体/读模型 | 核心约束 |
| --- | --- | --- |
| A | AdminAccount/Session/Invitation/Mfa、Role/Permission/Binding、AuditEvent、SensitiveAccessGrant、Alert | 邀请/令牌唯一且散列；独立身份；读授权限资源/人员/期限；审计应用层追加 |
| A | AdminUser/Order/Job 查询投影、GenerationLifecycleEvent | 可重建；分阶段事件幂等，保留真实事件时间 |
| B | ServiceCase、OperationRequest/Approval/Execution、UserRestriction、CompensationOrder、ProviderAdmissionGate | 不得自批；幂等执行；来源唯一；受理检查与状态变更协调 |
| B | OperationsOutbox、PromotionBudget | 外部意图持久化；补偿预算与账本一致 |
| C | ConfigDraft/Version/Activation、RuntimeVersionAck、CredentialReference、RetainedExecutionProfile | 不可变发布内容；一个活动指针；历史任务可解析旧版本 |
| C | RefundOrder、CreditRefundHold、RefundEvent | 稳定退款号；权益隔离；每订单首版仅一个有效全额退款流程 |
| C | ReconciliationImport/Line/Match、CostRevision、CashFeeEntry、RevenueAllocationVersion、FxRateVersion、ExportJob | 去重、证据绑定、追加修订；原币金额；不伪造逐任务分摊 |

不在本稿提前创建数据库表。迁移需向后兼容：先建表/读模型，再灰度切换管理入口；现有 User 增加限制字段或关系时默认正常。

保留钱包优先锁顺序；资金、补偿、退款与任务结算先锁 user wallet，再按确定顺序锁订单/批次及排序后的 provider scopes。实体自身用 version 或条件更新防止读后覆盖。网络、文件解析和对象存储访问在长数据库事务之外。

账务不变量：issued = available + held + consumed + expired + revoked；引入退款预留后明确扩展为含 refundHeld 的恒等式，逐一更新余额查询、分配、到期与验收，不能偷偷混进任务 held。支付与模型的未知外部状态各自恢复，不能跨域使用同一条“成功”状态。

## 14. 界面方向与页面结构

桌面优先；建议内容工作区最小 1280px，高密度表格不为手机强行缩成难以操作的卡片。窄屏允许只读查询，资金与配置发布引导到桌面完成。键盘导航和可访问性状态说明仍必须支持。

视觉基线：浅灰底、白色内容面板、石墨文字、单一蓝色强调；状态使用文本＋图标＋颜色。金额与积分等宽数字，型号 ID/业务 ID 支持一键复制。常驻醒目的测试/生产环境标记；不与用户端生成页面的创意视觉混淆。

布局：左侧导航约 224px；顶部为全局精确搜索、环境、待办与账户；内容区为标题、筛选、摘要和主表格。快速查阅用右侧详情抽屉，任务时间线/对账/模型规格使用可独立链接的完整详情页。

审批页同时展示申请内容、当前事实、影响范围、证据、已发生的补偿/退款与差异。危险动作采用独立确认页，不放进无说明的批量“更多操作”。无权限动作隐藏；有权限但条件不满足则禁用并解释原因。

这是文字交互方向，不是已经完成的高保真 UI 或可点击原型。原型与前端实现需在本稿确认后分别推进。

## 15. 内容与增长（二期边界）

用户自带参考图是复刻主入口；运营示例库只作为可选内容。示例需记录来源、授权证明/期限、公开副本、标签、推荐的已支持模型规格和版本。

流程：草稿 → 审核 → 已发布 → 下架；授权到期停止新入口，历史用户任务和私有结果不被删除。普通运营无权把用户私有图、提示词或人物素材直接公开；需要明确授权和独立审核。

不凭主观分数伪造外部平台销量或播放量。邀请奖励、免费重做和质量补偿要有独立补贴预算及账本来源，不通过修改订单实收或模型费用“美化利润”。没有埋点支撑的下载率、转化率显示未接入。

## 16. 非功能需求与告警

- 安全：默认拒绝、最小权限、MFA、CSRF、字段级脱敏、审批人分离。API/Worker/导出/日志都不得返回密钥。私有图不进入公共 CDN 或共享缓存。
- 审计：A 起记录成功/拒绝变更和敏感访问；应用账号无删除审计权限，日志向独立存储归档。保留期作为部署前须确认的策略配置，未明确时禁止生产启用，不宣称已满足具体法规。
- 性能目标：常规列表在 10 万用户/100 万 Item 验收样本、默认 30 条分页下 P95≤2 秒；长报表/导出异步。只是目标，必须压测，不是当前测量值。
- 报表聚合：可重建、标注 asOf 和滞后；实时查询和缓存异常不互相覆盖。生产默认排除模拟数据，测试环境全局显式标注。
- 告警：预算达到 80% 提醒，100% 阻止新受理；钱包恒等式异常立即告警；超截止仍冻结超过 2 分钟告警；未知率/落盘失败阈值由有版本的运营规则配置，规则未启用时明确提示。
- 告警需去重、归并、负责人、恢复事件与升级；邮件等通知失败通过待办仍可看见。首版不接外部团队聊天机器人。
- 首版不做批量删除用户、订单或资产，不运行无人审批的大规模资金动作。

## 17. 验收用例

1. 普通用户 Cookie、未完成 MFA 的管理会话无法调用管理查询；角色撤销后旧会话立即失去权限。
2. 客服看不到 Key、完整批量邮箱、未经授权的私有图；猜测资源 ID 不泄露存在性。
3. 没有真实模型/支付配置时显示未开通，不能展示为已联调；后台断网不回退 Mock 成功。
4. 不同角色对同一任务获得正确的字段和动作范围，直接构造请求也不能越权。
5. 同一管理员兼任角色仍不能自批；改申请参数、过期或 targetVersion 变化使审批不可执行。
6. 重复补偿执行、数据库中断、两个审批人竞争，最多生成一个批次和一组流水。
7. 已释放积分、原额度已过期时，客服页面展示实际可用增量，而不是笼统“全额到账”。
8. 支付同步与回调并发只履约一次；假截图或手工 paid 参数不能发积分。
9. 退款审批后用户抢先消费时执行拒绝；权益预留后不能再消费；退款超时保留同一退款号及预留。
10. 退款外部成功/内部失败可恢复，重复通知不重复回收积分；确认失败后的权益归还遵守原有效期。
11. 上游未知不可重发；已落盘恢复不增加 Attempt 或真实 API 调用；过截止不复活原任务。
12. 手工确认执行终止只释放执行槽，不把未知费用清零；人工对账与晚到 Worker 不重复减预算。
13. 模型规格只能在官方核验子集中选；被暂禁组合不能通过 API 强行发布。
14. 新配置发布时旧报价/任务仍解析旧版本；未就绪 Worker 不能执行新版本；暂停不能被历史报价绕过。
15. 提价只作用于新报价；停用不删除旧任务证据或使已接收付款无法收尾。
16. 同账单重复导入、无请求 ID 汇总账单、金额冲突均不会重复计费或自动伪造逐任务匹配。
17. 费用修订后报表只取当前有效版本；unknown 不按零；预算多 scope 不重复相加；零交付成本不除零。
18. 赠送积分收入为零；缺手续费/退款数据不能显示已确认毛利；模拟成本不混入真实经营报表。
19. 私有预览授权过期、审批撤销、导出下载失权后不再返回数据；CSV 文本公式不执行。
20. 审计写入失败时高风险本地操作不提交，外部意图可追溯；错误和审计中无密钥或原始图片。
