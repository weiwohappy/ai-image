# 微信与支付宝支付设计（未开通商户阶段）

用户已批准官方直连方案并要求先实现。当前没有商户凭据，不进行真实收款、部署、退款或商户注册。

## 范围

PC 网页首版：微信 Native 二维码、支付宝电脑网站支付跳转。只购买固定有效期积分包，不自动扣款、不售卖尚未实现的并发权益。此增量不实现原长期架构的逐月会员发放、现金退款及财务对账单导入；上线前仍需补齐退款运营流程、真实模型和商户联调。

## 边界

- 独立 `/api/billing` API 与前端付款服务，绝不调用旧 `/mock/orders/:id/complete`。默认 disabled，未配置时展示暂未开通。
- 商品价格、积分、有效期由服务端版本化配置提供；人民币整数分，积分整数；没有获批的正式价格时不能启用。
- 两个适配器实现 `create`、`query`、`verifyNotification`。网络调用在数据库事务之外；超时视为未知，使用原商户订单号查询，不换号自动重收。
- 微信请求 RSA-SHA256、响应/回调原始字节验签、公钥 ID 匹配、五分钟时钟窗口、AES-256-GCM 解密；支付宝用官方 Node SDK，RSA2 通知验签、应答验签。
- 独立 exact-path webhook 免 Origin 校验，不扩大到其余接口；无 cookie 权限，只有验签后的资金事实可进入履约。

## 订单与积分

订单保存用户、幂等键、请求摘要、版本化商品快照、渠道和商户身份快照、金额、币种、积分、有效期、唯一商户订单号、上游交易号、支付状态和 checkout。并发重复下单只派发一次。返回的收银台 URL 必须符合渠道域名/协议白名单。

确认到账共同入口核对渠道、商户、应用、订单号、总额、币种与上游交易唯一性。钱包锁先于订单锁；事件去重、订单 paid、付费积分批次与流水在同一个 SQL 事务提交。失败整体回滚，重复回调与查单竞争只发一批。付费积分与赠送积分分开标识；收入字段标注为实收总额而非扣除未知费率后的利润。

订单到期只关闭本地支付入口，不把未知事实改成未支付；迟到合法付款仍履约，积分有效期从实际履约起算，避免漏通知使用户收到已过期额度。关闭/等待通知不能覆盖 paid。付款事实与客户端返回页面/“已支付”点击无关。

## 恢复与前端

服务端轮询未结订单并限频；用户查单只读 SQL，手动同步为有鉴权限频 POST；恢复脚本可单次或常驻运行，不依赖图片 Worker 的生产模拟渠道开关。网络异常留下可恢复状态，不输出原文、凭据或支付者身份。

前端展示开通状态、订单金额、二维码/官方跳转、等待到账、超时与重试查询。刷新保留订单 ID，不保留凭据。收银台成功必须来自真实账本订单查询；演示账号与真实账号不混用，真实收款前要求后端会话。既有创作 Mock 继续保留。

## 验收

本地生成测试 RSA 密钥与加密通知，覆盖篡改、错商户、错金额、重复事件、不同订单复用交易、并发幂等、迟到付款、创建超时、回调/查单竞争、DB 回滚与恢复；不访问收费接口。前端验证未开通、401、等待/成功/失败、重新打开及安全跳转；全量构建与回归测试。
