# 运营平台：模型分辨率积分定价设计

日期：2026-09-10。状态：用户已确认功能方向；本详细设计待审阅，尚未开始编码或更改实际价格。

## 1. 目标与已确认规则

在运营后台新增“模型管理 → 积分定价”，管理不同模型、不同输出分辨率的单张图片积分。保存立即生效，不设置草稿审批或定时发布。

- 唯一计价维度为“官方模型 ID＋分辨率档位”，同档位下已支持的比例同价。
- 文生图、用户上传参考图的爆款复刻共用定价；本批不增加参考图、提示词长度或生成模式附加费。
- 总预估积分＝单张积分×生成张数。沿用现有1–4张限制、逐张冻结、成功扣除、失败/取消释放和幂等结算。
- 未定价或停用的规格不得创建新任务，不默认免费，不使用其他模型的价格兜底。
- 调价影响新报价；未提交的旧报价需重新确认；已提交任务按原积分结算，不因单纯调价失效。
- 没有 API Key 也可以先配置积分；价格启用不等于渠道可用，不自动启用模型调用。
- 用户积分售价与官方 API 成本分别管理，本批不修改成本费率、预算、凭据、模型协议和支付商品。

## 2. 范围与现状

现有 `CatalogService` 从 `OFFICIAL_IMAGE_MODELS_JSON.models[].sales` 读取价格；后台模型详情只读展示。执行快照的渠道指纹也包含sales，因此直接热修改现有配置会同时改变渠道标识。

本批将价格持久化到PostgreSQL，后台、真实模型目录、报价和任务提交使用同一个价格来源；将商业价格版本与API执行版本拆开。保留现有钱包与官方适配器的安全约束。

只修改 `viviai-server`、`viviai-admin` 及本功能的设计/计划文档。用户端 `viviai-web` 当前生成页面仍有独立Mock流程和价格表，本批不把该演示流程冒充真实计费、不切换它的身份/上传/生成协议，也不覆盖其现有未提交修改。验收中的真实报价与扣费由服务端HTTP集成测试证明；用户端完整真实生成接线是另一个交付项。

本批不提供会员折扣、按比例差价、按质量档差价、按API提供方对客差价、自动汇率定价、最低毛利承诺、批量导入UI、优惠券、财务补偿或现金退款。既有模拟图片保持明确模拟标识和隔离测试价格，不出现在官方模型积分配置中。

## 3. 界面与权限

### 3.1 入口与列表

保留现有“模型与规格”入口，在模型运行分组增加“积分定价”入口；从模型详情可进入该模型定价页面。内部路由为 `/model-pricing`，支持选择模型。

以“一行一个模型＋分辨率”列出：模型名称、官方模型ID、分辨率、已支持的比例、单张积分、价格状态、生成可用状态、版本、更新时间、操作。

- 未创建记录：显示“未配置”，积分显示“—”，版本为0，可新增。
- 启用记录：显示当前整数积分，可编辑、停用。
- 停用记录：保留原积分、版本和历史，可编辑、重新启用；不物理删除。
- 渠道未配置：单独显示“API未就绪”；不能把价格已启用显示为可以实际生成。
- 只展示 `officialSpecs(modelId)` 已存在的分辨率，并展示其有效比例/像素组合；禁止将两个枚举做笛卡尔积，不允许在此表单编辑尺寸。
- 1K/2K/4K等是当前产品档位，像素规格仍以已有审核白名单为准，不声称所有模型支持相同尺寸。

同一模型的各分辨率独立保存，不提供跨行批量保存。沿用蓝白后台表格和侧边表单，不增加新的视觉风格。

### 3.2 表单

模型、分辨率和适用比例为只读。积分必须为1–1,000,000之间的整数；拒绝0、负数、小数、空值、NaN、无穷值和字符串伪装的数值。

新增默认勾选价格启用，但必须明确点击保存；未保存内容不生效。编辑允许改积分和启用状态。停用/重新启用通过同一写接口提交完整目标状态。

显示旧值→新值、单张积分、示例张数的总积分以及“保存后新报价立即生效；已提交任务不变”。操作原因沿用5–500字符要求，提示不得填写密码、密钥或客户内容。只收到持久化成功响应后显示成功并刷新列表、详情和历史。

继承已有表单能力：字段级错误、键盘焦点、关闭草稿确认、保存中禁用、409保留输入并加载最新版本、403刷新权限、401清理会话、网络结果不确定时冻结输入并重试同一幂等键。价格服务失败不得回退到前端写死价格。

### 3.3 授权

读取使用现有 `models.read`。新增独立写权限 `model-pricing.write`，依赖 `models.read`；仅明确加入内置 `super_admin` 的本版本权限集合。该写权限不允许添加到自定义角色，其他内置角色不自动获得它。

价格操作同时要求当前有效会话、精确Origin、development、本机监听、本机管理Origin、实际请求来自回环地址。延续本项目本地预览边界，不开放生产写入。既有两个账号的密码、MFA例外、角色绑定和敏感权限不因本批改变。

后端每次写入必须重新授权；前端同时依据权限、运行开关及服务端 `allowedActions` 显示按钮，菜单隐藏不替代接口鉴权。内置角色迁移需同步数据库权限和代码目录，不能只改前端角色名称。

## 4. 数据设计与审计

新增 `ModelCreditPrice`：

| 字段 | 约束/含义 |
| --- | --- |
| id | UUID主键，供价格快照和审计关联 |
| modelId、resolution | 联合唯一；必须命中已有官方规格白名单 |
| unitCredits | 整数，数据库CHECK保证1–1,000,000 |
| enabled | 布尔，表示价格是否接受新订单 |
| version | 正整数，初始1；真实价格/状态变化递增 |
| createdAt、updatedAt | 数据库时间 |
| updatedBy | 管理员ID；离线维护导入可为空，并明确记录维护来源 |

数据库另约束modelId、resolution长度与version范围；具体型号与支持组合由同一个服务端白名单验证，不能任意新增模型名。删除/弃用官方规格后，其历史价格仍可追溯，但不再作为可售规格。

`GenerationQuote` 和 `GenerationJob` 各增加可空 `creditPriceSnapshot` JSON。新官方报价/任务必须包含 `{priceId, version, modelId, resolution, unitCredits}`；价格总额及每张积分仍使用现有BigInt列，服务端校验快照与列值一致。模拟及历史记录的空值有明确兼容路径，不把缺少快照视为免费。

不再把用户积分放入新的API执行快照；其中保留官方模型、协议/规格、渠道、凭据版本、上游成本费率与预算。价格快照与API快照分别承担商业结算和执行匹配职责。

复用只追加的 `AdminAuditEvent` 和 `AdminCommandReceipt`，不再建立第二套历史账本。审计新增白名单字段：modelId、resolution、beforeUnitCredits、afterUnitCredits、beforeEnabled、afterEnabled，继续使用beforeVersion/afterVersion/changedFields。创建时before值为空；操作原因只保存摘要，不存完整表单或秘密。

历史视图展示操作人/维护来源、时间、动作、前后积分/启用状态与版本；只读，按时间和ID稳定游标分页，默认30条、最多100条。仅返回该模型的定价成功事件，不泄露其他团队或客户审计信息。同值保存不增加价格版本，不使报价失效；仍产生一次可重放的操作回执及无实际变化的审计记录。

## 5. HTTP契约

复用现有 `{data,message,requestId}` 响应及错误code。端点均在 `/api/admin` 下：

| 方法与路径 | 用途 |
| --- | --- |
| GET `/model-pricing` | 返回官方模型全部已审核分辨率及价格记录，支持精确modelId筛选 |
| GET `/model-pricing/:modelId/:resolution` | 读取单行、有效规格、当前版本、状态和动作能力 |
| PUT `/model-pricing/:modelId/:resolution` | 新增或修改、停用/启用单行 |
| GET `/model-pricing/:modelId/history` | 读取该模型价格历史，支持resolution筛选及游标 |

写请求体严格为 `{unitCredits:number, enabled:boolean, expectedVersion:number, reason:string}`，携带UUID `Idempotency-Key`。新增expectedVersion=0，更新使用当前版本；没有“强制覆盖”参数。同键不同请求409，同键同请求重放结果，不重复修改版本或审计。回执至少返回 `{resourceId,version}`，刷新后读取实际行值。

定价行响应包括 `modelId,name,provider,resolution,specs,priceId,unitCredits,enabled,version,updatedAt,runtimeAvailable,availabilityReason,allowedActions`。未配置时priceId/unitCredits/updatedAt为空、enabled=false、version=0。`specs`只含公开尺寸与比例信息；availabilityReason为稳定枚举，不返回Key、原始配置、错误栈或账单。

`runtimeAvailable`仅表示已配置可用渠道/规格，不代表完成真实API联调。实际新报价可用还要求价格已配置且启用。列表明确区分 `unpriced`、`price_disabled`、`runtime_unavailable`、`available` 四种综合状态。

状态接口保留B1团队字段，新增 `modelPricingWritesEnabled`；界面按实际能力显示“团队管理＋积分定价”，不能由一个阶段标签推断所有业务模块可写。

原 `/api/models` 的公开规格价格改为数据库价格；仅返回运行配置可用且已定价启用的有效组合。旧字段保持兼容，不返回不支持组合；没有可用规格的模型不进入可生成列表。原生成报价响应保留unitCredits/totalCredits，增加可空priceVersion（模拟为空）。

## 6. 原子生效与报价/扣费

### 6.1 提交边界

当前价格不放入长时间驻留的进程缓存，管理查询和新报价从数据库读取已提交状态。多进程在保存成功后读取同一个新版本，不要求重启。

对模型＋分辨率建立统一事务级价格锁。后台写入沿用团队命令事务的鉴权/审计/幂等保护，并在操作价格行前持锁；顺序为团队全局锁→当前管理员锁→价格锁。新报价只拿价格锁；任务提交按已有钱包锁→价格锁，不反向申请管理员或团队锁。所有入口使用相同锁键，不用只在一个进程生效的内存互斥。

写入在一个事务内完成：重新授权→检查环境/权限→幂等检查→锁定目标价格→比较expectedVersion→校验官方规格→更新价格/版本→审计与回执。创建也必须锁定尚不存在的组合，防止并发新建。

新报价在价格锁保护下读取启用价格，记录价格快照和API执行快照，再计算总额。缺价格/停用返回可识别的不可用错误，不回退到JSON、Mock或模拟价格。

任务提交先处理既有幂等重放，然后在价格锁内检查报价有效期、价格ID/版本/积分、启用状态、API执行配置及输入摘要。若调价已提交，返回409 `PRICE_CHANGED`；若价格停用，返回409 `PRICE_UNAVAILABLE`，不创建任务、不冻结积分。客户端需要重新获取报价并由用户重新确认，不能自动接受涨价。

若任务先提交成功，之后的调价/停用不修改该任务的价格快照、冻结数额、扣除或释放额度。成功结算始终使用任务项保存的unitCredits，不能查询当前价反算。重复提交已存在的任务返回原任务，不因后来调价新增扣款。

继续使用五分钟报价有效期。调价后改回相同数值也属于不同版本，旧报价不能借此恢复有效。既有未提交的旧格式官方报价应明确要求刷新；历史已提交任务仍使用持久化每张积分结算。失败任务的人工重试是新的报价和任务，使用重试时现价并重新确认。

### 6.2 API执行版本解耦

新的渠道ID/能力版本只由API执行相关字段计算，不含数据库价格、价格版本或旧sales数值。官方适配器、路由、调用费用记录不使用对客积分作为API费率。

仅调价或停用售价不能重建/移除渠道，不会让已提交任务因找不到原渠道而失败。真实的凭据、模型能力或渠道配置发生变化，仍遵守既有执行校验与安全失败/释放规则，不承诺跨凭据变更继续调用。

价格启用与运行规格启用分离。启动配置引入 `enabledResolutions` 表示该模型允许执行的档位；它必须来自官方白名单，配置模型仍须有有效凭据及预算。为兼容旧部署，未提供enabledResolutions时可从旧sales的键解析原运行档位，但旧sales的数值不再成为运行期售价来源；两者同时存在时以显式enabledResolutions为准。

修改数据库售价不会改变运行档位集合。给尚未允许执行的分辨率配置价格只得到“价格已配置、API规格未就绪”，不擅自扩展API调用范围。

## 7. 迁移与本地预览

结构迁移增加价格表和可空快照字段，不重写历史积分、交易、图片、模型费用或任务执行记录。权限迁移只显式更新内置super_admin的新增能力；现有角色成员绑定不变，不顺便给owner/system_admin提权。定价授权从数据库角色源解析，测试覆盖代码与数据库一致。

启动不自动写价、不用Mock示例价格播种、不在每次重启时覆盖后台修改。提供显式本地维护导入入口：默认dry-run，读取既有官方配置的sales并列出目标模型/分辨率/积分，apply仅在不存在对应价格行时创建并记录维护审计；已有行无论启停均不覆盖。导入不改变凭据、API启用范围或模型成本，解析旧价格不要求发起API请求。无旧价格时不产生记录，由管理员手动配置。

正式应用迁移前：验证是本机预览数据库，备份并校验归档，确认没有活跃生成/提供方/支付操作，暂停本项目后台和工作进程；检查是否存在非终态旧格式官方任务。若存在不能安全继续的旧任务，停止升级并报告，不通过改写任务金额或伪造执行快照解决。历史终态任务保留旧快照可读。

本次应用环境的实际状态只能在维护阶段确认，不根据前一批的空库结果假定现在仍为空。待审核实施计划将明确进程归属、迁移、旧价导入dry-run/apply及恢复步骤。

新代码上线后只对新报价/任务写新快照。回退前保留备份并评估新字段/价格版本的数据兼容，不直接启动把JSON旧价当真价的旧代码。

本地预览继续使用现有3010管理前端和3011后端，不调用真实模型、支付或邮件服务，不进行部署/推送/合并。真实账号只用于登录及只读验收，不自动设置用户未提供的生产售价。

## 8. 代码责任边界

- `viviai-server/src/modules/catalog/`：新增独立积分价格读取、快照及价格锁单元；目录和报价调用它。
- `viviai-server/src/modules/admin/`：独立model-pricing控制器、命令和查询；沿用既有认证、审计、幂等及动作授权，不挤进通用大查询文件实现所有逻辑。
- `viviai-server/src/modules/providers/official-config.ts`、`official-runtime.ts`：执行规格与售价解耦；保留上游费用和凭据安全检查。
- `viviai-server/src/modules/generation/`：提交时核对价格版本，任务保存快照，调价不改变已提交执行与结算。
- `viviai-server/prisma/`：增量迁移、价格/快照结构、内置超级管理员权限更新。
- `viviai-admin/src/model-pricing/`：列表、单行编辑、历史和类型；复用现有表单、请求、错误、确认与刷新交互。
- 已有模型详情和导航：展示统一数据库价格及入口；原其他业务只读页面不扩展写操作。
- 本地测试：隔离schema、临时存储、模拟官方HTTP响应；实际AdminClient的新增→读回→报价变更端到端脚本。

前端Site文件仍由站点所属执行者修改。测试必须保护现有未提交的用户端工作，不使用真实客户图片或管理员账号作可写测试夹具。

## 9. 验收标准

1. 没有Key且没有启用官方模型时，后台仍能看到每个审核模型的支持档位并创建价格；公开可生成目录仍不能凭此宣称API可用。
2. 不支持档位/比例、非整数/零/越界价格、未知请求字段均拒绝；不能通过改URL创建任意模型。
3. 同模型同分辨率的有效比例统一价格；文生图/复刻一致；张数精确乘算，失败只释放对应任务项积分。
4. 两个独立服务实例共享数据库，实例A保存后，实例B的新报价读取新价；不需要重启。
5. 已取报价后调价：提交409，无任务/冻结；重新报价显示新价，确认后新任务使用新价。
6. 已提交任务后调价/停用：原任务仍可通过原渠道执行并按旧积分成功扣除或失败释放；API调用成本记录不被新积分污染。
7. 调价与提交并发结果只有“旧价任务先成功”或“调价先成功、旧报价拒绝”，不存在报价旧价却冻结新价的组合；重放同请求不重复版本/审计/扣款。
8. 自定义查询角色、普通管理员、降权后的旧会话、非本机请求、错误Origin及生产写操作均拒绝；原两个账号登录和B1团队功能回归通过。
9. 409保留草稿，403/401更新访问状态，网络断开不偷偷换键；未配置、停用、API未就绪、只读、加载、空值和错误状态可区分。
10. 审计记录操作人、时间、前后价格/状态/版本；不可修改或删除；响应与日志不包含Key、密码、客户提示词或图片。
11. 迁移保留历史记录；旧配置价格只能显式导入一次，不覆盖后台价；无旧价不伪造初始价；停用不物理删历史。
