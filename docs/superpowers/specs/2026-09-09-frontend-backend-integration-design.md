# VIVIAI 前后端业务闭环设计

日期：2026-09-09。状态：聊天中的范围已确认，本文待用户审核；尚未进入实现。

## 1. 目标与范围

将已有创作前端连接现有 NestJS 后端，打通同一账户下的登录、余额、上传、报价、任务、结果与资产管理。保留独立演示模式，不改现有视觉风格，不重建站点。

本阶段的“真实”指真实账户、数据库、上传文件、钱包事务和后台任务；图片仍由后端 `simulation-image-v1` 模拟渠道输出，必须标注“模拟图片（非 AI）”。不得称为 Nano Banana 生成、真实 AI 效果或正式上线版本。

纳入：

- 登录、注册、密码重置、注销及会话过期恢复。
- 创作页、付款页、侧栏、个人中心使用同一真实账户和钱包余额。
- 文生图，以及用户自己提供爆款参考图、可选主体图的复刻流程。
- 服务端报价、幂等提交、任务查询、取消、失败项重试、结果保存。
- 资产预览、下载、重命名、收藏、回收站及七天内恢复。
- 未实现功能在服务端模式明确禁用；保留独立 Mock 演示。

不纳入：真实模型提供方接入、生产部署、支付开通、实际付款/退款、自动续费、社区后端、工作流引擎、运营后台、动态商户/模型管理。保留现有安全审查与生产准入限制。

成功标准：同一账户可登录后上传自己的参考图，确认报价，提交复刻任务；后台完成后资产和钱包状态一致，刷新页面仍能找到任务及图片。断网、重复点击和重新登录不能被前端转换成新的重复任务。

## 2. 方案选择

采用“同一套页面 + 显式数据模式 + 服务契约适配层”。不是把原有 Mock 的所有接口直接代理到后端。

| 方式 | 取舍 |
| --- | --- |
| 推荐：显式 demo/server 模式、适配现有页面 | 保留演示体验；集中处理契约差异，避免每页各自判断和假成功 |
| 一次性删除全部 Mock | 尚未实现的工具、工作流、通知等会失去演示能力；改动范围过大 |
| 复制一套新的正式页面 | 初次隔离简单，但样式、修复、交互需要长期维护两份 |

后端继续作为身份、可用模型、价格、任务和账务事实来源。不会为了兼容演示而放宽后端参数校验、添加公开赠分接口或“模拟支付成功”接口。

## 3. 模式与启动隔离

由启动/构建配置 `VIVIAI_DATA_MODE=server|demo` 明确选择，构建时注入一个非敏感客户端常量；默认 server，非法值构建失败。测试显式设置目标模式。页面内不提供热切换按钮，也不根据接口请求失败自动切换。

- 主开发入口：server，沿用 `http://localhost:3000`。
- 单独演示入口：demo，使用不同端口 `http://localhost:3002`。通过明确脚本启动，不占用或自动关闭已有用户进程。
- 两种模式显示持久可见的模式标识。server 当前显示“后端联调 · 模拟图片（非 AI）”；demo 显示“演示数据 · 不用于真实交易”。
- server 将同源 `/api/*` 代理到现有 `127.0.0.1:3001`，包括私有图片内容；保持 Origin 和 Cookie 语义，不暴露跨域绕过鉴权的入口。
- demo 才启动 MSW；其付款入口仅显示演示模式不办理交易，不读取真实支付账户、不创建真实支付订单。
- server 不注册 MSW。启动时检查当前页面是否被本站已知 `/mockServiceWorker.js` 控制；只注销同源、匹配脚本路径和本应用 scope 的旧模拟注册，必要时执行一次有保护的重新加载。若仍受模拟控制则停在说明页，要求重新打开页面，不能继续渲染业务。不得清理无关 Service Worker、其他站点数据或全部浏览器缓存。
- Mock 初始化失败、后端不可用、配置错误都有独立错误状态；都不能永远显示加载中或伪造成功。

生产构建中的模式标签不等于生产准入。当前模拟模型在后端生产环境被禁止；本阶段不变更该限制。

## 4. 前端模块边界

继续复用现有路由、组件与样式。按职责新增/调整小模块：

| 模块 | 职责 |
| --- | --- |
| runtime/mode、capabilities | 启动模式、功能开关、模式标签、Mock 清理门禁 |
| services/http | 同源请求、超时、JSON 包装解析、错误映射、AbortSignal 支持 |
| services/server-contracts、adapters | 后端 DTO 与页面展示模型的明确映射，不导入服务器 Prisma/密钥模块 |
| services/api facade | 保留页面已有调用入口，按构建模式分派；server 未实现能力显式报不可用 |
| session/account hooks | 统一账户查询、登录/注销/过期处理、用户数据缓存边界 |
| generation/quote + submission | 报价快照、确认、持久化幂等提交、结果未知恢复及失败项重试 |
| assets/upload + restore | 真实 multipart 上传、服务端预览、草稿引用验证和回收站 |

现有 `billingApi` 继续管理支付接口和支付订单；server 模式的账户查询/会话事件与全站共享，不再维持第二套登录 UI 和独立余额缓存。支付协议适配器与后端履约事务不在本次重写范围内。

### 契约差异清单

| 现状 | server 模式处理 |
| --- | --- |
| MSW 无条件启动，只有 /api/billing 代理到后端 | 显式启动模式；server 全部业务走真实 API |
| Mock 登录预填演示账号，注册/重置使用至少 8 位密码 | server 不预填凭据；注册/重置 12–128 位，登录只检查非空及后端上限 |
| sendCode(email) 不区分用途 | 显式发送 register 或 reset-password；发送成功提示不包含任意验证码可用 |
| 本地 estimateCredits 决定展示价格 | 展示模型目录预估，实际提交必须使用服务端 quote |
| 生成 POST 直接传表单 | 发送严格 `{quoteId,input}` 与 Idempotency-Key |
| source=generation、quality=low/medium/high | 后端 DTO 使用 source=create/remix、当前模拟模型 quality=standard；两套类型分开 |
| Remix 写死 nano-banana-2、1K/2K/4K、多比例 | 读取后端模型，当前只提供 simulation-image-v1、1K、1:1、PNG、1–4 张 |
| 创建页构造 upload-UUID 和 blob URL 作为素材 | 真实上传得到服务器资产 UUID；不能把本地临时 ID 作为后端资产提交 |
| 任务只展示总体状态，重试只传任务 ID | 保留服务端 input、items、stage、cancelRequested；重试按实际失败项重新报价 |
| 流水为 delta、balance | 后端为 amount、heldDelta、consumedDelta、expiredDelta；按真实分录展示，不编造逐笔余额 |
| 资产搜索 query/source 被默认视为后端能力 | 后端仅支持 favorite/deleted；名称/来源在已加载的最多 200 项中筛选并注明范围 |

## 5. 统一账户与缓存安全

server 全站唯一账户事实来自 `/api/me`，支付账户别名与其属于同一 Cookie 会话。

- 查询 `/me` 返回 401 视为未登录；网络错误和 5xx 必须展示“暂时无法读取账户”，不能当成正常游客静默吞掉。
- 登录/注册成功后清除之前账户的私有缓存，写入新账户，回到安全的站内地址。禁止任意外链或协议相对地址作为 redirect。
- 注册用户名沿用后端规则：3–32 个小写英文字母、数字或下划线，提交时规范化。验证码 6 位。取消 server 模式“注册即送 5 积分”的固定承诺，余额以服务器为准。
- 重置密码使用独立 purpose；成功后清空本地会话和私有缓存，返回登录。不存在“重置后仍保留旧账户可操作”的状态。
- 任意受保护接口 401 触发统一会话过期事件，关闭付款弹窗，停止用户任务/资产查询并清理私有缓存。保留待处理的提交恢复记录供同一账户再次登录后查验，不自动提交。
- 账户查询键在 server 下被所有组件和付款页共享。任务、资产、流水和支付订单查询键至少包含 mode 与 userId；注销/切换账户取消在途查询，废弃旧会话响应，避免 A 用户请求迟到写入 B 用户画面。
- 模式、草稿、上传引用、提交恢复记录分别命名空间化。服务端资产引用只能在已确认所属账户下恢复；不能从 demo 的 `viviai-session-v1` 自动导入假资产 ID。
- 未登录时可输入文字，但上传要求登录。登录返回仅恢复文字/参数并展示报价入口，不像旧 Mock 那样自动恢复并执行生成。
- 个人中心显示实际可用/冻结积分、真实流水与账户基础信息。不把后端占位的 Free/concurrency 字段当作已承诺会员权益；改资料、换邮箱、兑换码、邀请奖励在 server 模式禁用。

开发验证码仍由现有后端邮件配置投递到私有本地目录；前端不新增读取验证码接口。端到端测试可以读取自己创建的隔离测试邮箱文件。实际联调账号通过现有注册或手动配置 seed 创建，不植入固定登录密码。

## 6. 模型与报价交互

当前 server 模型目录是 simulation-image-v1，1024×1024 PNG，30 测试积分/张，1–4 张。这只是现有后端测试价格，不是对未来真实模型的定价承诺。

- 模型与可用分辨率、比例、格式来自 `/api/models`；空目录显示未开通，禁止提交。
- 新的 server 草稿可以初始化为明确展示的首个可用模型。已保存的模型下架时显示不可用并要求用户重选，不偷偷替换旧模型或降分辨率。
- 页面模型选择、草稿实际值和提交值必须一致；不允许控件展示首个模型但仍提交旧 nano-banana-2 ID。
- 模型目录 unitCredits×张数只作“预估”；不调用旧 Mock 的成本表为 server 作价。
- 用户点击“获取报价/开始生成”后调用 `POST /generation-quotes`，展示本次模型、参数、总冻结积分和报价有效期，再由用户明确点击“确认生成”。复刻使用同一报价确认逻辑。
- 任一相关字段改变均使当前报价失效；不会拿旧报价继续提交，也不在每次敲字时创建数据库报价记录。
- 后端返回规范化 input；提交时使用该报价对应的完整快照，不重新展开可能已经变化的表单。
- 报价到期或明确的 QUOTE_EXPIRED/QUOTE_USED/QUOTE_MISMATCH 提示重新获取报价，并重新确认。余额不足显示实际余额和缺口；支付未开通时说明无法充值，不跳到模拟充值。

## 7. 提交、恢复和任务管理

统一提交状态：editing → quoting → quoted → submitting → accepted；传输结果不确定时进入 uncertain。状态来自实际响应，不用定时器伪造成功。

提交前保存恢复记录：mode、userId、operation、可选 retryOfJobId、quoteId、规范化 input、随机幂等键、创建时间。包含提示词，不含密码/Cookie/密钥。记录无法可靠保存时阻止提交并说明原因。

- 双击与组件重渲染不产生新幂等键。HTTP 超时、断网、5xx、响应解析失败均保留原记录。
- uncertain 状态提供“重试确认原任务”和“查看任务列表”；重试发送原 quoteId、原 input、原 Key、原 operation，不能先重新报价或换 Key。
- 后端对已受理的相同请求优先返回原任务，即使报价已过期。只有明确未受理的业务错误才回到修改/重新报价流程。
- 未知结果未处理完前，不允许把同一记录改成另一张新图的提交；成功受理后保存任务 ID 并释放该次提交状态。清理记录时核对记录标识，不能删除新的进行中尝试。
- 刷新后向同一已登录账户显示恢复提示，不自动发送收费性质的写请求；不同账户看不到或复用原记录。恢复记录只保证当前浏览器保存的请求，不宣称跨设备、清空浏览器数据后的全局防重。
- `/generation-tasks` 列表最多 100 个最新任务，不能宣传完整分页历史；已知任务 ID 可使用详情接口单独查询。
- 有进行中任务时约每 2 秒查询一次，后台标签页暂停定时轮询，401 停止；网络错误展示暂时断连及重试，不把任务改为失败。
- stage=unknown 表示仍在核实执行结果，materializing 表示正在保存结果；进度来自后端。执行中取消只显示“已请求取消”，直到服务端给出终态；不提前宣称积分退回。
- 任务进入终态或新增结果资产后刷新资产、余额、流水；已有结果即使任务 partial 也可查看。
- 重试只对全部出图项已终结、且至少一个 item.status=failed 的任务开放；取消项不当成失败重试。保留原规范化 input，仅将 count 改为失败项数量，重新报价、确认后调用原任务 `/retry`，使用新的独立幂等键。
- 展示“失败释放冻结积分，过期积分按账户规则处理”，不声称所有失败都增加可用余额；现金退款不属于这里的积分释放。

## 8. 用户参考图、草稿与资产

server 的文生图只接收文字；需要参考图时明确引导到“爆款复刻”，携带已有文字要求，不在后台把 create 静默改成 remix。资产的“用作参考图”也跳到复刻页。

复刻必须由用户提供一张已上传的参考图；主体图可选且不得与参考图相同。旧平台模板详情/模板库只留在 demo；server 模板深链显示功能未接入并提供上传入口，不把模板 ID 当成资产 ID。

- multipart 仅提交 file，后端决定实际尺寸和格式。前端预检 JPEG/PNG/WebP、5 MiB 上限，但不能以浏览器元数据代替服务器验证。
- 上传完成前不得引用；响应采用服务端 UUID、名称、宽高、previewUrl。预览为同源私有地址，Cookie 鉴权；不保留 object-store key，不向外站传图。
- 用户快速更换文件时，只有最新选择的上传可以写入当前草稿；旧请求迟到不覆盖新参考图。失败保留错误/重试状态，不冒充上传成功。
- server 草稿按 userId 保存已完成上传的引用，不保存 blob URL 或 File。刷新后用资产详情重新校验权限、状态和可用性；404/删除/非本人引用清空对应图片并说明需要重选。
- 引用图删除或退出账户时清理当前私有预览和选择；不能复用另一个账户的图片草稿。demo 继续保持原本本地上传刷新后需重传的行为。
- 资产列表、预览、下载、收藏、重命名、删除和恢复使用真实接口；下载由用户点击触发，使用同源私有内容，不把图片复制到第三方下载服务。
- server 资产页提供回收站，查询 deleted=true，七天内可恢复；不仅限于本次页面内存中的撤销提示。无物理删除按钮。
- 批量收藏/删除/恢复逐项展示结果：成功项刷新，失败项保留选择并显示错误；不能把部分失败说成全部成功。删除确认仍保留。
- 资产名称和来源搜索明确是已加载结果中的本地筛选；server 只展示当前支持来源，不虚构工具/工作流产物。

## 9. 未实现功能和自动化入口

server 的可用路由：登录/注册/重置、创建、用户上传复刻、任务、资产、账户钱包、付款。

灵感社区、平台模板库、AI 工具、工作流、邀请奖励及服务端通知尚无后端，不调用 Mock，也不显示伪造通知数。导航和页面深链均由统一能力表控制；不可用页面说明“暂未接入”，而非跳转到假数据。

顶部不能硬编码“创作系统运行正常”；模式标签和 API/模型加载结果分别反映状态，不用健康检查冒充外部 AI 已开通。

WebMCP 工具注册与相同能力表一致。server 不注册 resetDemoData、completeMockOrder、未实现工具/工作流动作；已支持动作使用同一真实 API 与服务端报价/幂等规则。能够产生生成任务的自动化入口不得绕过网页中的报价确认：可以开放模型/状态查询和准备草稿，获取报价属于创建报价记录的准备动作、不是只读查询；最终提交先留在用户确认流程，不增加静默执行能力。

## 10. 错误处理与展示边界

- 映射后端常见业务码为中文：INVALID_CREDENTIALS、INVALID_CODE、ACCOUNT_EXISTS、RATE_LIMITED、INVALID_INPUT、MODEL_UNAVAILABLE、INSUFFICIENT_CREDITS、报价错误、幂等冲突、资产不存在等。
- 区分未登录、无权限/不存在、服务不可用、网络中断、输入不合法与订单结果未知；不得 catch 后返回假的空列表/成功对象。
- API 非 JSON 或未知错误显示安全通用文案与可用的 requestId，不显示 HTML、堆栈或完整私有输入。
- 账户余额继续使用安全整数显示；流水展示 available/held/consumed/expired 变化，不通过最新 200 条流水倒推不存在的完整历史余额。
- 不改后端金额单位、报价 TTL、钱包锁序、支付回调验证、关闭开关或模拟模型生产禁用规则。

## 11. 验收与测试设计

实施使用测试驱动：每个新增行为先有能观察到失败的测试，再实现。测试 fixture 明确是测试，不放进 server 运行时。

1. 模式隔离：server 不启动 Mock、旧模拟控制器阻止业务直到清理；demo 不发真实支付请求；非法配置不回退。
2. 账户：注册/找回 purpose、密码规则、真实验证码提示、401 后重新登录、A→B 账户隔离、迟到响应不污染、付款与创作余额共用。
3. 模型与报价：空模型、下架模型、真实参数与控件一致、输入变化失效、报价到期、无报价不能提交、不使用 Mock 定价。
4. 幂等：双击一次受理、超时同 Key/同 quote/input 恢复、刷新后同账户恢复、不因重新登录自动执行、不同账户隔离。
