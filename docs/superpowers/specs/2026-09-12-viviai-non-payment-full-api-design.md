# VIVIAI 非支付功能全量 API 化与运营内容管理设计

日期：2026-09-12  
状态：待最终审阅  
范围：`viviai-web`、`viviai-server`、`viviai-admin`  

## 1. 背景与目标

当前用户端的登录、模型目录、生成报价、普通生成、爆款复刻任务、素材管理和积分流水已经连接真实后端；灵感、爆款模板、AI 工具、工作流、批量任务、通知、邀请、账户资料及兑换码仍依赖 Mock 数据或在真实 API 模式下被拦截。运营平台已经具备查询、团队权限、模型渠道与积分定价能力，但尚无内容运营模块。

本次改造的目标是：

1. 除支付外，用户端所有现有页面和操作均由真实后端 API 支撑。
2. 运营平台能够管理灵感、爆款模板、AI 工具、内容媒体、兑换活动和兑换码，并查询工作流及批量任务。
3. 普通生成、爆款复刻、AI 工具和工作流统一进入同一套报价、积分冻结、模型路由、任务执行和失败退款流程。
4. 生产模式不再出现“仅 Mock 模式可用”的页面；Mock 模式只作为演示与自动化测试能力保留。
5. 所有内容修改、营销资源发放和高风险任务操作均受权限与审计保护。

## 2. 非目标

以下内容不在本次范围内：

- 修改或联调微信支付、支付宝支付。
- 改变已有支付订单和支付回调的数据模型。
- 新增聊天、视频生成或与现有图片产品无关的功能。
- 向用户端或运营端返回模型渠道密钥、验证码、密码哈希或供应商原始敏感载荷。
- 将运营内容图片混入用户私有素材库。

## 3. 实施策略

采用纵向分阶段交付，每个阶段同时完成数据库迁移、后端接口、用户端或运营端页面以及自动化测试：

1. 账户与互动：资料、头像、邮箱和密码修改、通知、邀请、兑换码。
2. 内容运营：灵感、爆款模板、AI 工具、内容媒体及用户点赞收藏。
3. 工具执行：工具预报价、提交、积分冻结、生成任务关联和结果展示。
4. 工作流与批量任务：持久化、整批报价、逐行执行、取消和失败项重试。

数据库与 API 契约在第一阶段统一确定，减少分阶段开发中的重复迁移和接口返工。

## 4. 总体架构

`viviai-server` 是所有业务状态和价格的唯一事实源。两套前端不得自行确定积分价格、模型能力、任务最终状态或账户余额。

系统按以下边界拆分：

- `account`：用户资料、安全验证、头像、邀请和兑换。
- `engagement`：通知、点赞、收藏等用户互动状态。
- `content`：灵感、爆款模板、工具定义及运营媒体。
- `tool-execution`：工具字段校验、提示词编译、报价和生成任务创建。
- `workflow`：工作流编辑、批量报价、运行编排及失败恢复。
- 现有 `generation`、`wallet`、`catalog`、`provider-routing`：继续承担模型能力校验、积分、渠道选择和执行。
- 现有 `admin`：增加内容与营销命令接口、权限判断及审计记录。

用户端和运营端共享 DTO、状态枚举和错误码定义。前端可以保留独立视图模型，但 API 边界不得继续复制 Mock 专用结构。

## 5. 数据设计

### 5.1 用户与账户

在 `User` 增加：

- `avatarAssetId`：可空，指向用户自己的头像资源。
- `inviteCode`：唯一且不可变，用于用户邀请。
- `invitedByUserId`：可空，仅记录首次有效邀请人。
- `updatedAt`：资料变更时间。

新增：

- `Notification`：`userId`、`type`、`title`、`body`、`action` JSON、`readAt`、`createdAt`。
- `Referral`：`inviterUserId`、`inviteeUserId`、`status`、双方奖励快照、`qualifiedAt`、`rewardedAt`。每个被邀请用户只能有一条有效关系。
- `RedemptionCampaign`：活动名称、有效期、单用户领取限制、积分数量、总量限制、状态和版本。
- `RedemptionCode`：码摘要、展示掩码、活动 ID、状态、最大使用次数和已使用次数；数据库不保存可直接导出的明文码。
- `RedemptionClaim`：用户、兑换码、获得积分、时间及幂等键。唯一约束防止重复领取。

兑换成功沿用现有 `CreditLot` 和 `CreditEvent`，以 `campaign/code/claim` 组成稳定 `sourceId`，保证重试不重复发放积分。

### 5.2 运营内容与媒体

新增 `ContentMedia`，字段包括对象存储键、摘要、内容类型、宽高、字节数、状态、创建人和时间。内容媒体与用户 `Asset` 隔离：前者可被已发布内容公开读取，后者始终按用户权限访问。

新增内容实体：

- `Inspiration`：标题、描述、标签、封面/案例媒体、默认提示词、模型建议、排序和状态。
- `InspirationLike`：用户与灵感作品的唯一关联。
- `RemixTemplate`：标题、描述、标签、参考媒体、视觉分析 JSON、默认提示词、参数建议、排序、状态和版本。
- `RemixTemplateFavorite`：用户与模板的唯一关联。
- `ToolDefinition`：名称、描述、图标/封面、字段 Schema JSON、提示词模板、默认模型、尺寸/比例约束、输出数量限制、排序、状态和版本。

内容状态统一为：

`draft -> published -> offline -> archived`

归档代替物理删除。用户查询仅返回 `published`；运营查询可以按全部状态筛选。每次工具或模板执行均保存内容版本和编译后的输入快照，因此后续编辑或下架不影响历史任务。

### 5.3 工作流与批量任务

新增：

- `Workflow`：用户、名称、列定义 JSON、版本、归档时间和更新时间。
- `WorkflowRow`：工作流、稳定行 ID、排序、单元格 JSON 和更新时间。
- `WorkflowRun`：用户、工作流、工作流快照、报价快照、总项数、各状态计数、状态、幂等键和时间。
- `WorkflowRunItem`：运行、工作流行快照、序号、状态、错误码、关联 `GenerationJob`。

`Workflow.version` 用于乐观锁。保存时客户端提交上次读取的版本；版本不匹配返回 `409 WORKFLOW_VERSION_CONFLICT`，不静默覆盖。

`GenerationJob` 增加可空来源信息或关联表，用于标识 `direct`、`remix`、`tool`、`workflow`，以及对应工具版本或运行项。它只影响追踪，不改变已有任务执行状态机。

## 6. API 设计

所有受保护用户接口使用现有会话认证。所有命令接口接受幂等键；时间、积分和分页格式沿用已有 API 约定。

### 6.1 用户端内容与互动

- `GET /inspirations`
- `POST /inspirations/:id/like`
- `DELETE /inspirations/:id/like`
- `GET /remix-templates`
- `GET /remix-templates/:id`
- `POST /remix-templates/:id/favorite`
- `DELETE /remix-templates/:id/favorite`
- `GET /tools`
- `GET /tools/:id`

列表接口返回当前用户的 `liked` 或 `favorited` 状态。重复点赞、收藏或取消操作保持幂等。

### 6.2 账户、通知、邀请与兑换

- `PATCH /account/profile`
- `POST /account/avatar`：multipart 上传；服务端校验图片格式、大小和归属。
- `POST /auth/send-code`：扩展 `change-email` 和 `change-password` 用途。
- `POST /account/email`：验证新邮箱验证码、唯一性并撤销其他会话。
- `POST /account/password`：验证当前登录邮箱验证码，修改后撤销其他会话。
- `POST /account/redeem`
- `GET /notifications`
- `POST /notifications/:id/read`
- `POST /notifications/read-all`
- `GET /invites`

修改邮箱和密码不采用仅凭当前会话直接修改的方式。验证码用途、目标邮箱和用户身份必须匹配；验证码不可跨用途复用。

### 6.3 AI 工具执行

- `POST /tool-run-quotes`
- `POST /tool-runs`

报价请求包含工具 ID、工具版本、字段值、素材 ID、模型和输出规格。服务端执行：

1. 校验工具仍已发布且版本可执行。
2. 按工具 Schema 校验字段及素材归属。
3. 编译提示词与生成参数。
4. 使用模型能力目录严格验证分辨率、比例、数量和参考图限制。
5. 调用现有报价服务生成短期报价，报价中冻结工具版本和执行快照。

提交时必须携带报价 ID 和幂等键，随后进入已有生成任务流程。前端不得提交自行计算的积分价格或任意未声明模型参数。

### 6.4 工作流与批量运行

- `GET /workflows`
- `POST /workflows`
- `GET /workflows/:id`
- `PUT /workflows/:id`
- `POST /workflows/:id/copy`
- `DELETE /workflows/:id`
- `POST /workflow-run-quotes`
- `POST /workflow-runs`
- `GET /workflow-runs/:id`
- `POST /workflow-runs/:id/cancel`
- `POST /workflow-runs/:id/retry-failed`
- `GET /batches`
- `GET /batches/:id`

批量报价对每行执行与工具执行相同的服务端编译和能力校验，并返回每项价格、总价和不可执行行。默认只有所有选中行均通过校验时才可提交。

提交后整批预冻结积分，每个生成项独立结算；失败或取消项释放对应冻结积分。批次允许部分成功。`retry-failed` 只为失败且可重试的项生成新报价和新任务，不复用已消费报价。

### 6.5 运营端

为以下资源提供列表、详情、新增、编辑、发布、下架、归档和排序接口：

- `/admin/content/media`
- `/admin/content/inspirations`
- `/admin/content/remix-templates`
- `/admin/content/tools`

为以下资源提供管理接口：

- `/admin/redemption-campaigns`
- `/admin/redemption-codes`
- `/admin/referrals`
- `/admin/workflows`
- `/admin/batches`

兑换码支持批量生成、禁用和使用记录查询。明文码只在批量生成成功的单次响应中返回，之后只显示掩码；导出功能导出本次生成结果，不提供从数据库恢复明文的能力。

工作流和批次主要为查询及故障处置。运营人员可取消未开始或仍在排队的项、重试确认属于系统故障的失败项，但不得修改用户工作流内容。人工动作必须记录原因和审计事件。

## 7. 运营平台页面

新增导航：

- 内容运营：灵感库、爆款模板、AI 工具、内容媒体库。
- 营销运营：兑换活动、兑换码、邀请奖励记录。
- 任务运营：工作流、批量任务。

内容列表支持关键字、状态、标签、更新时间筛选及拖拽或批量数值排序。编辑器支持媒体上传/选择、字段配置、默认模型和规格、提示词模板、预览、保存草稿、发布、下架、复制与归档。

发布前服务端再次验证必填媒体、工具字段 Schema、提示词模板引用、模型能力和积分定价。前端校验只用于提升体验，不作为安全边界。

## 8. 权限与审计

新增权限族：

- `content.inspirations.read/write/publish`
- `content.templates.read/write/publish`
- `content.tools.read/write/publish`
- `content.media.read/write`
- `redemptions.read/write`
- `referrals.read`
- `workflows.read/manage`
- `batches.read/manage`

权限遵循现有“按权限集合而非角色名称”原则：

- `super_admin` 拥有全部权限。
- `content_operator` 默认拥有内容读取、编辑和发布权限，但不拥有客户敏感内容权限。
- 系统管理员、业务负责人及自定义角色根据实际权限集合显示菜单和操作按钮。
- `write` 依赖对应 `read`，`publish` 依赖对应 `read + write`，`manage` 依赖对应 `read`。

以下操作必须进入已有操作审计：内容新增/编辑/发布/下架/排序/归档、兑换活动和兑换码变更、积分发放、批次取消与重试。审计差异不得包含密码、验证码、密钥、用户完整提示词或参考图内容。

## 9. 前端行为

- 移除真实 API 模式下对灵感、爆款模板、工具、工作流和邀请页面的拦截。
- 首次加载显示骨架或加载态；刷新失败时保留已有数据并提供重试。
- 点赞和收藏采用乐观更新，失败自动回滚并提示。
- 所有表单展示字段级错误；保存期间防止重复提交。
- 工具和工作流执行前展示模型、尺寸、比例、数量、单项积分、总积分和当前余额。
- 批量详情展示总数、排队、运行、成功、失败、取消、已消费积分和已退回积分。
- Mock 模式继续可用，但生产构建的默认配置必须指向真实 API；Mock 数据不得回退覆盖真实接口错误。

## 10. 错误与一致性

统一业务错误至少覆盖：

- `CONTENT_NOT_FOUND_OR_OFFLINE`
- `CONTENT_VERSION_CONFLICT`
- `WORKFLOW_VERSION_CONFLICT`
- `INVALID_TOOL_INPUT`
- `UNSUPPORTED_MODEL_SPEC`
- `QUOTE_EXPIRED`
- `INSUFFICIENT_CREDITS`
- `IDEMPOTENCY_CONFLICT`
- `REDEMPTION_INVALID_OR_EXPIRED`
- `REDEMPTION_LIMIT_REACHED`
- `BATCH_NOT_CANCELLABLE`
- `PROVIDER_TEMPORARILY_UNAVAILABLE`

HTTP 语义：认证失败使用 `401`，权限不足 `403`，不存在或对当前用户不可见 `404`，版本/幂等冲突 `409`，业务校验 `422`，限流 `429`，临时基础设施故障 `503`。

数据库事务边界确保报价消费、任务创建和积分冻结同时成功或同时失败。Worker 的任务领取和结算沿用 fence、lease、outbox 及现有幂等机制。重复请求不得重复创建任务、重复发放积分或重复消费兑换码。

## 11. 测试策略

### 后端

- 单元测试：状态转换、权限依赖、工具 Schema 校验、提示词编译、报价快照和错误映射。
- 数据库集成测试：点赞收藏唯一约束、内容版本、工作流乐观锁、兑换并发、报价消费与积分冻结事务、批次部分成功退款。
- API 契约测试：用户端和运营端所有新增路由、分页、错误响应、权限拒绝和敏感字段过滤。
- Worker 测试：工具来源快照、批量任务进度汇总、取消、失败项重试和重复消息。

### 用户端

- API 服务测试：真实模式请求路径、DTO 转换和错误处理。
- 页面测试：加载、空态、编辑、收藏回滚、报价确认、余额不足、冲突和批次部分失败。
- 路由测试：真实模式下所有非支付页面可访问。

### 运营端

- 权限导航与按钮可见性测试。
- 内容新增、编辑、发布、下架、排序和归档测试。
- 工具发布校验、兑换码单次明文展示、批次人工操作原因及审计测试。

### 端到端冒烟

1. 管理员创建并发布工具。
2. 用户刷新后看到该工具，完成报价并提交。
3. 后端冻结积分，Worker 创建结果素材并结算。
4. 用户收到通知并在素材库看到结果。
5. 用户建立多行工作流，提交批次，查看部分成功/失败并重试失败项。
6. 管理员下架工具，用户列表不再显示，但历史任务仍可查看。

## 12. 验收标准

- 用户端除支付外所有现有菜单均在真实 API 模式完成读取和写入。
- 收藏、工作流、通知、邀请、兑换和批次在刷新及重新登录后保持正确。
- 运营端完成内容新增、编辑、发布、下架、排序、复制和归档。
- 工具和工作流严格使用官方模型能力目录支持的尺寸、比例和参考图约束。
- 所有模型执行入口统一使用服务端报价、积分冻结、渠道路由、成功结算和失败退款。
- 重复提交、并发保存、余额不足、内容下架、渠道失败和批量部分失败均有自动化覆盖。
- 支付代码保持现状，本次测试不要求真实支付成功。
- 任何 API 响应和审计记录均不泄露渠道密钥、验证码、密码哈希或未经授权的客户敏感内容。

## 13. 迁移与兼容

- 使用可回滚的 Prisma 迁移增加表、索引和可空字段；先扩展、再启用新代码，不破坏已有任务与资产。
- 为现有 Mock 灵感、模板和工具编写幂等种子导入，按稳定外部 ID 更新，不重复插入。
- 新接口上线后前端通过配置切换到真实 API。Mock handler 保留用于测试，但不作为真实 API 失败时的自动后备。
- 现有生成任务和支付订单无需数据回填；新来源字段保持可空。
- 内容媒体初期使用现有存储抽象的本地实现，生产部署时可切换对象存储而不改变 API。

## 14. 安全与运维

- 上传文件校验 MIME、扩展名、大小、图片解码结果和哈希；对象键由服务端生成。
- 用户素材按所有权授权，内容媒体只在关联已发布内容时允许公开缓存读取。
- 验证码、兑换、邀请绑定、内容发布和批次人工操作均实施频率限制。
- 渠道密钥只通过后端环境变量或密钥存储加载，配置 API 只返回掩码及验证状态。
- 为内容发布失败、批量失败率、积分冻结异常、通知积压和兑换异常增加结构化日志与运营告警入口。
