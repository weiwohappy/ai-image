# ViVi AI 单位经济与利润测算

> 核算日期：2026-08-31  
> 汇率假设：1 USD = 6.7297 CNY  
> 结论范围：模型调用层面的毛利，不等于公司净利润。

## 1. 核心结论

1. **Nano Banana 有 Google 官方 API**，通过 Gemini API 和 Vertex AI 提供。
2. 目标站四个“香蕉”名称与 Google 官方模型名称一致，可以较高置信度映射到官方模型。
3. 如果目标站按 Google Gemini API 的 Standard 官方标价采购，用户把套餐积分全部用完时，当前香蕉模型全部是负毛利。
4. 该商业模式要盈利，至少需要满足以下一项：
   - 用户只消耗少量积分，大量积分按月过期；
   - 获得 67%–85% 左右的上游折扣或使用更低价渠道；
   - 将批量工作流路由到价格减半的 Batch API；
   - 低价模型承担大部分请求，高价模型受到额度或隐性限制；
   - 套餐展示的积分并未全部形成真实模型调用。
5. 无法仅靠前台核实公司“净利润”。还需要后台真实模型 ID、Google/上游账单、用户积分使用率、任务失败率、支付手续费、税费、存储/CDN 和客服成本。

“盈亏平衡积分使用率”的含义：套餐用户平均使用的积分比例低于该数值时，未使用且过期的积分才可能补足官方模型成本。该比例尚未扣除服务器、存储、支付、税费、退款、审核和客服成本，所以真实安全线还要更低。

## 6. 一个直观例子

以标准月卡和 Nano Banana 2 1K 为例：

- 用户付款：¥36.8。
- 获得：1,000 积分。
- 4 积分/张，理论最多生成 250 张。
- Google Standard 官方模型成本：250 × ¥0.4509 = **¥112.73**。
- 如果积分全部使用，模型层毛利：¥36.8 - ¥112.73 = **-¥75.93**。

使用率场景：

| 实际积分使用率 | 实际生成张数 | 模型成本 | 模型层毛利 |
|---:|---:|---:|---:|
| 20% | 50 | ¥22.55 | ¥14.25 |
| 30% | 75 | ¥33.82 | ¥2.98 |
| 50% | 125 | ¥56.36 | -¥19.56 |
| 100% | 250 | ¥112.73 | -¥75.93 |

所以这个套餐若走官方 Standard API，Nano Banana 2 1K 的平均积分使用率必须控制在约 **32.6% 以下**，才有模型层面的正毛利；考虑其他成本，建议低于 25%–28%。

## 7. 该产品可能如何赚钱

### 7.1 积分过期是核心设计

月卡积分到期失效，季卡/年卡每 30 天重置。用户购买的是“可用额度”，不是平台已经发生的模型成本。大量未使用积分即 breakage，是最可能的利润来源。

### 7.2 用户分层交叉补贴

- 低频用户购买后很少生成，为平台贡献高毛利。
- 高频用户可能亏损，但被低频用户补贴。
- 高价年卡的每积分收入更低，必须依赖更低的平均使用率或更低采购价。

### 7.3 上游成本可能不是官方零售价

若用户高频使用仍能盈利，说明平台可能拥有企业折扣、批量价、预付采购价、海外大客户合同或第三方聚合商价格。仅凭前台无法确认其真实采购渠道。

### 7.4 将异步任务路由到低价通道

工作流和不要求实时返回的任务可以使用 Batch API，将模型输出价格降低约 50%。但除 Nano Banana 2 Lite 外，其余模型在积分全部使用时，即便按 Batch 价格仍普遍负毛利。

### 7.5 低价模型路由

平台可以在相似营销名称下按任务质量、用户等级或拥堵情况路由到更低成本模型。但若未向用户明确披露，存在产品信任和合规风险。

目标站只收 3–6 积分。因此，若我们使用官方 Standard API，不建议照抄它的积分价格。更稳妥的做法是：

- 以实时上游成本生成动态积分价。
- 为成本波动预留 10%–20% 缓冲。
- 首页实时任务和 Batch 工作流分开定价。
- 失败自动退款，但记录已产生的不可退上游成本。
- 套餐只承诺每月额度，不承诺无限并发或无限期余额。

## 9. 中国大陆部署注意事项

Google 当前官方可用地区列表没有中国大陆。官方条款要求 API 客户端在可用区域内使用服务。因此，中国大陆团队若要正式商用，通常需要合规的海外主体/项目与部署区域、Gemini Enterprise Agent Platform，或合法授权的上游服务商；真实价格和合规成本会与公开 Gemini Developer API 价不同。

## 10. 计算边界

- 汇率采用 2026-08-31 市场参考值 6.7297；实际结算会受信用卡、Cloud Billing 和汇兑费影响。
- 官方价格页最后更新于 2026-08-28，价格会变化。
- 未计算文本输入、参考图片输入、Thinking、搜索 Grounding、存储、CDN、审核、支付费、税费和客服。
- 未核实目标站后台实际使用的模型 ID，也未取得其采购发票，因此只能判定“官方零售价场景下的单位经济”，不能宣称目标公司实际亏损或盈利。
- 目标站的 G-image 2 不能仅凭 UI 名称确认底层模型。虽然名称可能让人联想到 GPT-Image-2，但目标站提供 4K 选项，而 OpenAI 官方 GPT-Image-2 说明为最高 2K，因此不能直接按 OpenAI 价格计入。

## 11. 利润核实所需后台数据

若要把“推算”升级为真正的利润审计，需要导出最近 30 天：

1. 各模型实际请求量、成功量、失败量和分辨率分布。
2. 每个请求的真实上游 model ID 与账单金额。
3. 各套餐付费用户数、收入、退款和支付手续费。
4. 已发放积分、已消耗积分、已过期积分和赠送积分。
5. 用户平均积分使用率及 P50/P90/P99 分布。
6. 存储、CDN、服务器、内容审核和客服成本。

核心公式：

```text
模型层毛利
= 套餐收入
- Σ（各模型成功请求数 × 单张真实采购成本）
- 失败但被上游计费的请求成本

净利润
= 模型层毛利
- 支付手续费
- 云资源与存储/CDN
- 税费
- 人工、客服、营销和退款损失
```
