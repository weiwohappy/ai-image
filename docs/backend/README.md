## 已确定的设计基线

- 模块化单体，同一代码库部署 API、Worker、调度/对账进程；先不拆微服务。
- PostgreSQL 是任务和账务事实来源；Redis/BullMQ 负责调度加速，丢失队列不等于丢失订单。
- 一个用户任务可包含多个出图项，每个出图项可有多个上游尝试；用户只为交付成功的图片结算一次。
- 产品模型、真实上游模型、提供方渠道、凭据、价格版本分别建模。
- 参考图与主体图分角色传递；正式上传落私有对象存储，刷新后能恢复。
- 自动切换只允许能力等价、成本可承受、数据地域允许的渠道；不能静默换模型或降分辨率。
- 未知上游结果先查询、等待或对账，不能把网络超时直接当成“没生成”。
- 用户积分账与提供方现金成本账分开。前端 Mock 的 3–6 积分等示例价格不作为生产采购/销售定价。
