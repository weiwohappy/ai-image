# VIVIAI 内部运营平台 · B1 团队管理

独立管理员身份和真实管理 API。默认关闭，没有默认管理员、Mock 业务数据或用户端登录回退。

## 当前范围

- 工作概览：按角色显示数据；未知成本、未接入的退款/手续费/利润显示“暂不可用”。模拟成本与真实成本分开。
- 用户、积分批次/流水、支付订单、生成任务与调用详情的只读查询。
- 模型与官方原生规格矩阵、提供方的本地预算/并发、运行告警。
- 团队成员：查询、邀请新增、编辑显示名称、分配角色、启用/禁用、生成密码重置链接。
- 邀请：查询、编辑名称/角色、重新生成链接、撤销；角色变化使旧链接失效，已使用的邀请仅供查看。
- 角色：查看内置角色，新增/编辑/删除未被引用的自定义查询角色。自定义角色自动勾选依赖权限，不包含团队写权限或客户敏感内容。
- 操作审计始终只读。真实 `super_admin` 可管理管理岗位；系统管理员和业务负责人可管理普通成员。本人只能改自己的显示名称，不允许禁用/改角色/重置自己；至少保留一位可登录的超级管理员。
- 邮箱邀请 → 密码 → MFA；初次验证后的一次性恢复码。
- 显式 `sensitive.read` 权限的成员可按任务填写原因，申请最多 5 分钟的提示词/图片访问；图片通过带管理员会话的私有接口加载，授权到期、切换页面、隐藏标签页或退出时清除。

模型/提供方配置、调价、补偿、现金退款、人工重试、导出和内容运营尚未开放写操作。B1 不会把这些模块标为已完成。

## 本地启动

需要 Node.js 22.22.2（最低 22.13）。在本目录运行：

```sh
npm ci
npm run dev
```

前端固定使用 `http://localhost:3010/`；端口占用时直接报错，不自动改端口。现有用户端的 3000 端口不变。

`/api/admin` 默认代理到 `http://127.0.0.1:3001`，保留浏览器 Origin。自定义本地后端可在启动时设置 `ADMIN_BACKEND_URL`。这是开发服务器配置，不能当成生产反向代理。

后端需要：

1. 按 `../viviai-server/ADMIN.md` 配置 PostgreSQL/Redis、执行正式迁移流程。
2. 设置 `ADMIN_ENABLED=true`、精确 `ADMIN_ORIGINS=http://localhost:3010`，以及独立随机的 32 字节 base64 `ADMIN_MFA_ENCRYPTION_KEY`。密钥只留在后端密钥存储/私有环境文件，不能使用 `VITE_` 前缀，不能提交。
3. 新环境通过后端离线流程邀请**两位明确指定的初始成员**；首次超级管理员需执行后端带目标邮箱、版本和原因的命令。已有环境先备份，再执行已审查的迁移；迁移不会自动把任何账号升为超级管理员。
4. 将邀请链接私下交给对应成员。链接使用 `#/accept?token=...&email=...&displayName=...`，不把 token 放在页面查询参数中；页面读入内存后立即从地址栏清除。24 小时内单次使用。邀请失败/过期请联系系统管理员。

后端未启用显示“管理入口尚未启用”；服务不可达显示连接错误。只有真实验证通过才显示管理数据。

## 团队变更流程

- B1 写入仅在 development、服务监听本机、全部管理 Origin 为本机且实际请求来自本机时开放。正式环境不允许启用；前端读取后端实际写入开关。
- 创建成员生成一次性邀请链接，不发送邮件。复制失败可手动复制；关闭后不可重新查看原链接，需重新生成使旧链接失效。
- 重置密码生成 30 分钟有效的单次链接，同时撤销目标旧会话；不直接替用户设密码，不解除原有 MFA。本人用链接提交新密码后需重新登录。
- 修改要求填写 5–500 字符原因并确认；冲突会保留草稿，需加载最新记录再保存。网络结果不确定时锁定提交内容，使用同一操作凭证重试以避免重复写入。
- 角色变更、禁用及密码重置会撤销相关旧会话。成员邮箱不可修改；审计与业务记录不会因禁用删除。

## 安全与部署边界

- 管理会话只使用 HttpOnly cookie；密码、TOTP 密钥、恢复码仅临时存在 React 内存中。不使用 localStorage/sessionStorage 保存认证信息。
- 客户端收到 401 立即清除受保护的视图，并拒绝旧请求晚返回的数据。闲置 30 分钟本地清屏；后端独立检查闲置 30 分钟/绝对 8 小时期限。不会轮询刷新闲置会话。
- 退出时先清屏再请求撤销服务端会话。如果撤销未确认，会明确提示重试，不能把本地清屏理解成服务端已退出。
- 所有权限和授权在后端强制检查。菜单隐藏只是交互提示，不是安全边界。
- 密码默认至少 12 位；仅后端明确启用的本机开发测试例外会显示短密码提示。单独启用短密码不改变双重验证；额外开启 `ADMIN_LOCAL_PASSWORD_LOGIN` 后，指定账号可用邮箱和密码直接登录。前端消费后端 `{account}` 响应进入工作台，其他账号仍按后端 MFA 挑战处理。指定邮箱范围和本机请求校验始终由服务端强制执行，正式环境不允许该例外。
- 时间展示为 Asia/Shanghai；CNY 分、USD 微元和积分以整数字符串处理，避免大额精度丢失。
- `.openai/hosting.json` 的空对象仅满足保留模板的本地构建要求，没有托管项目 ID、D1/R2 或外部部署。本项目复用 Vinext/Sites UI 工具链，不使用模板的本地 ChatGPT 登录身份授权后台。
- 不暴露 WebMCP 写工具，不增加会绕过身份确认的代理操作入口。
- B1 仍拒绝生产环境启用。生产验收还需要独立域名/HTTPS/CSP、外部不可篡改审计归档与留存、密钥轮换/恢复、安全测试和容量压测。单纯 build 成功不表示可部署处理真实财务操作。

## 验证

```sh
npm test
npm run typecheck
npm run build
npm run lint
```

安装相邻 `viviai-server` 的锁定依赖后，还可使用开发者提供的本地数据库/Redis 运行真正的跨端 HTTP 测试：

```sh
DATABASE_URL=postgresql://YOUR_LOCAL_TEST_DATABASE REDIS_URL=redis://YOUR_LOCAL_TEST_REDIS npm run smoke
DATABASE_URL=postgresql://YOUR_LOCAL_TEST_DATABASE REDIS_URL=redis://YOUR_LOCAL_TEST_REDIS npm run smoke:team
```

此测试直接使用本应用的 `AdminClient`，仅在自动创建的随机测试 schema 内完成邀请、MFA、会话、模型详情、任务与私有图片授权/过期/退出，并清理自己的测试数据。它不创建真实团队账号。

`smoke:team` 另外验证真实客户端的角色新增/分配/删除、成员编辑/启停、密码重置单次使用、邀请轮换/MFA 激活、本地指定账号登录、旧会话失效；使用同样的隔离 schema 和临时存储，不访问真实模型/支付接口。

测试中的固定人员、图片字节和响应只存在 `*.test.*` / `src/test`；不会进入应用的业务接口或生产数据。后端真实 HTTP 与数据库集成测试使用独立随机测试 schema，详见后端说明。没有调用真实模型或支付服务。
