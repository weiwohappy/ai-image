## 覆盖的支付安全和恢复行为

- 未开通时不产生订单或渠道请求；价格、积分和有效期由服务端控制，客户端不能传金额。
- 同一幂等键并发下单只提交一次；超时保留原商户订单号，不自动重建订单。
- 微信原始响应/通知 RSA 验签、时效与密钥 ID 校验、AES-GCM 解密；支付宝官方 SDK 的 RSA2 签名、原始响应验证和单次表单解码。
- 严格核对商户、AppID、订单号、渠道、整数分金额和 CNY；响应大小、等待时间及重定向受到约束。
- 并发回调与查单统一履约；事件、付费积分批次、流水、paid 状态原子提交；错误金额、交易号复用或事务失败不发积分。
- 成功通知只在数据库提交后确认：微信 HTTP 204 空体，支付宝纯文本 success；异常不伪造成功确认。
- 订单归属隔离、查单租约、持久化补偿扫描、合法迟到支付的幂等到账。
- 前端仅服务端 paid + fulfilledAt 显示到账；未知结果重试原订单；过期入口隐藏；真实账户与创作 Mock 账户隔离。
- 会话 401 清除过期真实账户并返回登录；暂停新销售仍能查历史订单；恢复最近订单不会错误占用旧购买缓存。
